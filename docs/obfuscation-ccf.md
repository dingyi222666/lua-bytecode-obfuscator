# Lua 5.3 / 5.4 / 5.5 统一控制流混淆算法设计

本文只定义算法、证明义务、伪代码级流程和验收条件，不包含实现代码。所有新增特性均为待验证设计；本文不宣称它们已经通过测试，也不把论文中的结果直接迁移为 Lua 上的强度结论。

总原则：以已验证的最小 CFF 为唯一语义内核，以参数化变换扩展同一个实现，以每原型翻译验证决定是否提交。任何“难以分析”都必须注明攻击模型和测量方法；任何“保持语义”都必须有前提、局部证明和组合证明。

## 1. 统一 CFF 主算法

### 1.1 语义契约与唯一实现

**算法步骤**

1. 为每个目标 VM 建立不可变的语义清单 `V`：精确版本及源码摘要、opcode 编号和字段、整数位宽、浮点配置、指令取指规则、隐式寄存器读写、帧顶读写、可能的调用/分配/关闭/yield、跳转方向和偏移基准。
2. 清单以对应 VM 的可执行语义为准。opcode 名称和注释只作索引，不能覆盖 VM 实际行为；尤其不从“都是 5.4 风格”推导 5.5 的布局。
3. 保留一个解码器接口、一个语义 IR、一个 CFF 规划器、一个按版本编码的 emitter。最小版就是该实现的 `baseline` 配置；完整版是同一实现的特性组合。废弃损坏实现的生产入口，不保留隐式二选一路径。历史输出可留作离线回归资产。
4. 每个原型输入保存 CFF 前的已验证快照 `P₀`。所有候选在事务副本中构造；只有完整验证通过才替换 `P₀`。
5. 定义可观察投影 `Obs`：返回值个数、类型与值；原程序可达堆与 upvalue 的修改；I/O；错误对象；元方法、关闭、yield/resume 的顺序。注入的控制状态只能存在于被证明不逃逸的私有状态中。
6. 明确适用边界：若程序观察自身字节码、物理 PC、寄存器局部布局、逐指令 hook、精确分配/GC 时机、栈轨迹文本或运行时间，普通 CFF 本身就不能保持这些观察。必须有已存在的运行环境契约、兼容映射，或拒绝受影响原型；不得默默把这些差异从测试中删掉。
7. 对新分配特别严格：私有表也可能改变 GC、终结器时机和内存失败。不能证明该影响不可观察时，关闭表模式；不能靠“表没有逃逸”单独证明分配透明。

正确性目标是保持所有原程序观察的双向对应，而非仅“新程序返回值看起来相同”：

`Obs(Execute_V(P₀, input)) = Obs(Execute_V(P′, input))`

对未终止程序使用有限可观察轨迹及分歧保持；对注入步骤使用有限停顿模拟，禁止引入无穷控制循环。测试超时只能记为未知，不能证明两个程序都不终止。

### 1.2 从字节码构造不可拆单元

**算法步骤**

1. 完整解码后先建立指令消费关系，再建立普通基本块。消费关系包括“执行时自动取下一条”“条件跳过下一条”“附加字归属于前一条”。
2. 对关系做闭包，生成带合法入口、出口、内部标签的原子单元。闭包包括：
   - 所有比较/测试与其紧邻 `JMP`；保留 `TESTSET` 条件写回。
   - 5.4/5.5 算术或位运算与对应 `MMBIN/MMBINI/MMBINK`，包括参数翻转位。
   - `LOADKX/EXTRAARG`；需要附加字的 `SETLIST`；5.4/5.5 的 `NEWTABLE/EXTRAARG`。
   - 5.3 `LOADBOOL` 的跳过行为、5.4/5.5 `LFALSESKIP` 及其被跳过指令。
   - 所有版本的 `TFORCALL/TFORLOOP` 连续取指单元。
3. 外部跳转若落在合法内部入口，扩大为保持该入口的多端口保留单元；不得擅自把它改成单入口块。目标若是 `EXTRAARG`、不允许独立进入的 MM 尾指令或其他非法位置，区分无效输入与当前模型不支持，禁止继续猜测。
4. 在合法单元边界上，以入口、所有显式跳转目标、条件跳过的两个后继、终结指令之后的位置建立 CFG。不可达代码也要解码和检查结构，不因不可达而允许非法编码。
5. 将数值 for 的准备、循环控制、控制寄存器窗口及方向关系记录为一个循环约束组；将泛型 for 的 prepare、call、loop、关闭变量关系记录为另一个组。循环组是共同规划、共同验证的对象，不等于必须把整个循环体永久合成一个大块。
6. 对 `top` 做独立数据流分析，标出开放多返回值的生产者、转运区间和消费者。无法在中间证明注入保持 `top` 的区间，合并成无注入区域；区域中原有控制流可原样保留。
7. 到达不动点后再计算块活跃性、捕获位置、关闭栈状态、调用破坏区、寄存器窗口和循环热度。任何后续切块或克隆都使相关分析失效，必须重算。

“不可拆”禁止插入、独立调度、独立重排破坏原子语义；不禁止在保留单元内部保留原有多入口标签。

### 1.3 版本语义矩阵

| 对象         | Lua 5.3                                                          | Lua 5.4                                                   | Lua 5.5                                                     |
| ------------ | ---------------------------------------------------------------- | --------------------------------------------------------- | ----------------------------------------------------------- |
| 比较         | `EQ A B C`：`RK(B)==RK(C)` 与 `A` 的关系决定是否跳过下一 JMP     | 依据比较 opcode 的操作数类型及 `k` 判断                   | 单独清单；不得复用数字 opcode 或字段解释                    |
| TEST 极性    | `C=1` 时真值执行下一 JMP，假值跳过；按 VM 真值规则处理 nil/false | 使用该版本 `k` 语义                                       | 使用该版本 `k` 语义                                         |
| 普通 JMP     | 有符号偏移；`A≠0` 还关闭从 `R[A−1]` 起的 upvalue                 | 使用相应有符号字段；关闭另行建模                          | 同样独立建模关闭与跳转                                      |
| 数值 for     | 保留原生准备、递增、比较语义；原生寄存器窗口包括 `A..A+3`        | 整数路径 count-based，用户控制变量在 `A+3`                | 整数路径 count-based，用户控制变量在 `A+2`                  |
| 浮点 for     | 保留 VM 浮点语义                                                 | 仍是浮点循环路径，不能按整数 count 重写                   | 同样不能按整数 count 重写                                   |
| 方向约束     | 按有符号跳转字段及合法性处理                                     | `FORLOOP/TFORLOOP` 向后；`FORPREP` 向前                   | 同 5.4 的方向要求，但寄存器副作用按 5.5                     |
| 泛型 for     | `TFORCALL` 消费紧邻的 `TFORLOOP`；两条的 A 关系按原字节码验证    | `TFORPREP` 直接取目标 `TFORCALL`，后者再取紧邻 `TFORLOOP` | prepare 会调整控制/关闭变量位置；call/loop 使用变化后的布局 |
| 可变参数准备 | 无 `VARARGPREP`                                                  | 需要时必须首先执行且只执行一次                            | 同样固定于入口；另建模新增可变参数相关 opcode               |
| 动态 top     | `VARARG B=0` 等按版本清单识别                                    | `VARARG C=0`，不能把 B=0 规则机械搬来                     | `VARARG C=0` 以及该版本其他字段/新 opcode                   |

在已核对的 5.5 VM 中，整数 for 的 count 在 `R[A]`，step 在 `R[A+1]`，控制变量在 `R[A+2]`。泛型 for 的 prepare 将关闭变量置于 `R[A+2]`、控制变量置于 `R[A+3]`，call 使用从 `A+3` 开始的调用区。模型应由对应版本源码锁定；不能仅信任仍沿用旧布局的注释。

### 1.4 边编码与循环落脚点

**算法步骤**

1. 为每个块建立语义出口表：无条件、条件真/假、循环继续/退出、返回、尾调用，以及必须原生保留的连接。错误和 yield 是指令语义的一部分，不改造成普通成功边。
2. 普通非终止边 `b→t` 在原副作用全部完成后进入边胶囊：构造运行期控制包，然后进入选定 dispatcher。
3. 条件边保留原来的比较/测试+JMP 单元；只把两出口接到不同边胶囊。不反转极性来“试着对齐”；如需反转，必须用该版本真值表验证。
4. 5.3 原 `JMP A≠0` 先按原条件执行关闭并落到边胶囊；所有纯注入 JMP 使用不关闭 upvalue 的形式。不得把关闭副作用复制到另一条分支。
5. 5.4/5.5 `FORLOOP` 的继续目标接到位于该指令之前的专用落脚点；落脚点构造去原循环体的控制包。指令之后保留退出落脚点。进入循环控制指令的路径跳到指令本身，不能先执行其前方落脚点。
6. `FORPREP` 的跳过目标必须位于其后方，进入循环路径走 fall-through 落脚点；按 VM 的 `pc+Bx+1` 规则计算，而非套用普通 JMP 偏移。
7. `TFORCALL/TFORLOOP` 作为连续单元移动。5.4/5.5 的 `TFORPREP` 目标仍必须是对应 `TFORCALL` 本体，不得以普通跳板替换这个取指目标。该连接是受约束的原生边，可保留不平坦化；记录实际覆盖率。
8. 遇到不能局部满足的循环、开放 top 或关闭约束，扩大保留区域。若仍能安全处理其外部边，可保留区域并继续；否则本原型拒绝 CFF。
9. `RETURN/RETURN0/RETURN1/TAILCALL` 保留版本相关字段、返回个数、关闭和 vararg 修正语义，不先跳 dispatcher 再模拟返回。

### 1.5 主流程与不变量

伪代码级流程：

> 对每个原型独立执行：锁定语义清单 → 保存快照 → 解码并构造原子单元 → CFG/top/关闭/活跃性分析 → 规划受约束循环与可改写边 → 从请求配置求可证明的实际配置 → 分配安全槽位 → 构造控制包、dispatcher 与边胶囊 → 在约束下排布 → 编码 → 独立解码 → 检查结构、模拟关系及最终 pass 组合 → 通过则提交；否则丢弃候选并按降级链重试。

核心模拟关系 `R` 在每个原语义单元的入口/出口成立：

- 原寄存器的活值、原堆、upvalue、关闭栈与 `top` 满足原程序的同一状态关系。
- 注入值只占用该时刻已死且安全的槽位，或有独立安全证明的槽位。
- 有效控制包唯一指向一个合法后继；解码无歧义。
- 到达该后继前只执行有限、无原程序可见副作用的管理步骤。
- 原指令的调用、错误、yield 与关闭顺序完全保留。

**失败时降级策略**

先撤销引发额外义务的特性，再尝试同一内核的已验证配置；不得把验证失败的候选原地修修补补后输出。基线也无法证明时恢复该原型 CFF 前快照。父、子原型分别决定；保持参数、upvalue 接口和既有寄存器映射，禁止因父原型回退留下子原型描述符的半提交修改。

**验证判据**

全部指令组与方向约束成立；所有原边有对应出口；所有被改写边有局部模拟证书；有效控制包总能有限步到达唯一后继；动态 top、调用破坏区和关闭状态的证明无未知项。跨版本分别对同版本原程序做差分，不能要求三种不同编码的字节码互相逐字节相同。

## 2. state 编码算法

### 2.1 运行期来源与可证明的非恒定性

**算法步骤**

1. 在每个可改写边入口收集可安全读取的活值与已经发生的分支事实。优先使用原程序已有数据；禁止调用 `_ENV` 中的随机数、时间、转换函数，禁止增加外部 I/O。
2. 无类型证明时，只用不触发元方法的真值测试把原值投影为整数位。只有证明原值为整数时才允许整数混合；不能让注入算术对任意用户值触发 `__add` 或转换错误。
3. 为种子表达式保存来源、类型证明、定义到使用链和可变化性证据。理想证据是在相同边上下文存在两个可行原状态，得到不同种子。仅有污点标记不够：`x−x`、恒真谓词返回值、支配分支已固定的条件都不合格。
4. 构建时随机数只用于站点布局与模板选择，不能宣称是运行期不可折叠来源。
5. 没有可证明运行期变化来源的边使用较低配置；若某预设要求所有受保护边都具有动态 state，则该原型不能标为满足该预设。零参数且行为完全固定的函数不能凭空得到无副作用的运行期熵。
6. 控制包尽量只在“边胶囊→dispatcher→目标块入口”存活。进入原块后可将其视为死值，下条边重新从当前原状态取得种子；这避免不必要的跨 CALL 长驻键。

“运行期不可折叠”的可验证含义是：state 数值在合格运行状态下不是编译期常量，并且指定的常量传播/局部化简攻击器无法消去其全部运行期依赖。它不是“任意静态分析器都无法恢复后继”的定理。特别是 `P_K(i)=P_K(j) ⇔ i=j` 可被识别双射的分析器利用；仅加一个运行期 key 不足以保证抗反平坦化。

### 2.2 局部编号空间与 keyed 双射

为每个源块 `b` 建立局部命名空间 `N_b`，其中编号描述该块的出口、等价克隆入口或网关，不是全原型共享的裸 case ID。不同命名空间允许复用局部编号，但不得脱离命名空间解释 token。

**算法步骤**

1. 给每个命名空间选择最小足够的 `M_b=2^m`，涵盖其合法局部编号；动态编码要求 `M_b≥2`，未使用编号保持非法，不能成为默认后继。取值范围和中间运算由目标整数位宽证明，不使用高熵 32 位随机 case 常量。
2. 对运行期种子 `K`、命名空间和 dispatcher 路线做域分离，生成 `a_b(K)` 与 `c_b(K)`，并证明 `a_b(K)` 始终为奇数。
3. 定义：

   `P_{b,K}(q) = (a_b(K)·q + c_b(K)) mod M_b`。

   奇数乘子在模 `2^m` 下可逆，故每个固定 `b,K` 上都是双射。这里使用模环算术是为了编码与可逆性，不计作 MBA 强度；不做算术/位运算混杂的未验证 MBA。

4. 对命名空间标识本身使用另一组运行期双射；逻辑控制包为 `(encoded_namespace, encoded_local_q, route_context, key_context)`。只有完整控制包决定后继。每个候选测试必须检查完整上下文，不能只因 token 数值相等就命中。
5. 命名空间域分离必须体现在生成规则及验证中，而非只改变量名。数值 token 可碰撞，但完整控制包不能对两个不同后继产生歧义；域分离不宣称密码学独立。
6. case 比较值在运行期由同一已证明编码构造。可使用从运行期起点出发的模环递推枚举候选；不在常量池写入“每块一个 state 常量”的列表。
7. 小序号、算法参数和结构位置不是秘密。大序号需要展开时，以经过证明的指令组合构造；5.3 无立即数捷径也不能用明文 case 表替代。常量池可以有公共算术参数，不能有专用的明文 case ID 映射。
8. 5.4/5.5 的所有生成算术按 opcode 规则配齐 MM 尾指令。虽然类型证明让 MM 分支不可达，仍不能破坏取指结构。

**不变量**

- 每个实际控制包的来源、命名空间、类型和范围已知。
- `Decode_b(K, Encode_b(K,q))=q`，合法局部编号的编码互异。
- 跨命名空间解释被拒绝，或显式执行经过证明的重编码。
- 长驻 `K` 只有在全生命周期安全时才存在；否则使用每边短生命周期控制包。

**失败时降级策略**

种子不可变化、整型范围不成立或 key 槽位不安全：撤销该边的动态编码资格，降低原型实际配置；编码碰撞、逆变换不成立属于正确性故障，整份候选作废。不得悄悄将运行期 key 固定为零后继续报告完整版。

**验证判据**

小域穷举双射和命名空间交叉解释；大域使用位向量证明及边界测试。对种子运行双执行关系检查，证明至少存在可行状态使 token 改变。对边→dispatcher 的完整数据流做化简，不只检查赋值右侧；报告成功消去 key 后恢复的真实边比例。

## 3. dispatcher 加固与安全网

### 3.1 分段、嵌套与多 dispatcher

**算法步骤**

1. 按命名空间、控制包类型、循环热度和寄存器压力，将 case 分配给若干段。分段预算来自成本模型，不按特定 fixture 的块数特判。
2. 将段组织成有限有向无环管理图，或具有严格下降排名函数的有界图。每段只测试一部分候选；段间可以经过收敛式不透明分支。
3. 第一层可解析运行期命名空间，第二层解析局部 token；其间允许切换到不同 dispatcher 实例。嵌套不能改用 Lua 函数递归，否则会改变调用、yield、栈和 hook 行为。
4. 由原程序运行期种子、已建立的控制上下文和有限路由状态选择 dispatcher。不能只按块 ID 在编译期固定“块 b 永远走 D₀”。对每个可选路线分别验证相同逻辑后继。
5. 每个 dispatcher 的 case 顺序和段布局独立规划。实例数大于一并不自动带来收益；必须确认运行中确实可选择多个实例，且不同实例不是只有常量改名的复制。

### 3.2 有实际 use 的内部副作用

**算法步骤**

1. 在段入口持有编码 token `S`、运行期 key 上下文及游标 `H`。
2. 某段选择可逆更新 `U`，令 `S′=U(S)`；之后本段及后继段的候选比较值必须经过同一已知变换，或使用等价的组合解码。
3. 同时更新游标/路由上下文，令后续段选择、候选生成或目标验证依赖该更新。删除更新而保留后续消费者应能产生反例；否则它没有有效 use。
4. 收敛式不透明分支的两臂可以执行不同的私有可逆更新，再在汇合口规范化到同一逻辑控制包。恒定结果的谓词只是成本层；另可使用运行期真分支选择语义等价路线，两臂都必须正确。
5. 更新不得写原程序活值，不得调用元方法，不得修改可见堆；使用的每个寄存器均需独立安全证明。这里的“副作用”是后续调度实际使用的私有状态变化，不是任意给程序增加外部副作用。

这些设计分别对应 IOLLVM 的嵌套思路、D810 提出的非常量 state/多 dispatcher/副作用困难，以及 Lebedev 方法的单一控制寄存器、连续 dispatcher 假设。普通 Lua 字节码没有通用 computed goto；本设计不声称实现了机器级间接跳转。多字段状态也可能被高级工具合并为一个表达式，不能据此直接判定攻击失败。

### 3.3 安全网

**算法步骤**

1. 为有效控制包建立 `Valid` 谓词，证明初始入口产生有效包，所有边编码和段更新保持有效性。
2. 快速路由未命中时，仅允许进入接受同一有效包的完整剩余解码路径。剩余路径由同一 emitter 生成，按编码规则确定唯一合法后继；不是第二套 CFF 实现。
3. 剩余路径不得把 nil、零、某个默认编号当作修复值，也不得随便跳原入口、返回空值、复制一个“最像”的后继。
4. 末尾安全网 RETURN 只能作为被证明不可达的结构性尾指令保留。它不是异常 state 的语义恢复器，不具有抗分析价值。
5. 若无法证明有效包永不落入安全网，候选不得输出。运行期检测只能帮助发现错误，不能替代编译时拒绝。

**不变量**

所有选择路线实现同一逻辑解码；每次副作用更新都有使用链且保持编码关系；管理图有限终止；有效包恰好命中一个目标；终端安全网从合法执行不可达。

**失败时降级策略**

撤销嵌套、实例或段更新后重新验证。最终可以回到已验证基线，但必须标为基线，不得将无副作用的直筒单 dispatcher 计入完整版。剩余解码路径可能帮助攻击者归一化，应一并纳入对抗测试。

**验证判据**

对每个包域验证唯一命中与终止；对每个路线验证逻辑后继一致；做副作用删除变异测试；审计跨段真实数据依赖。记录简单比较链扫描、局部符号执行和语义归一化后的边恢复率，而非仅记录 dispatcher 数量。

## 4. 入度混淆、布局洗牌与直线块切分

### 4.1 入度混淆

**算法步骤**

1. 在 CFF 后预计 CFG 上计算真实块、等价克隆块、管理块的入度分布，同时计算循环深度、执行权重、寄存器压力。语法入度和可行边入度分开统计。
2. 只在类别可由入度显著区分且有成本预算时增添等价入口。对一条真实边建立若干网关，运行期选择一个网关；各网关执行不同但经验证的私有控制变换，最终落到同一语义块。
3. 需要克隆时复制完整语义单元及其出口契约。选择克隆不得重复执行原副作用，且不能改变捕获寄存器身份、关闭顺序或外部入口语义。
4. 不透明死分支只补充语法入度；不能把不可行边算作运行期可行入度。优先使用可实际到达的等价网关和等价副本。
5. 真实块与辅助块的入度差距减少只是 IOLLVM 方向的结构指标。按照 CaDeCFF，不能据此宣称抗语义去混淆。

**不变量**：每条原边的所有替代路径都精确执行一次相同语义；所有新增可行路径最终到达合法后继；没有可到达的陷阱副本。

**降级**：单站点无槽位或闭包/关闭证明困难则不增边；若结构收益只来自不可达假边，降为低成本噪声或关闭该特性。

**验证**：路径等价证明、可行性检查、原副作用次数检查；分别报告原始入度分布与语义归一化后的分布。类别分类器 AUC 下降可作为结构收益，但不能代替真实边恢复率。

### 4.2 块布局洗牌

**算法步骤**

1. 把指令组、入口前缀、原生取指目标、循环方向、偏移范围、已有保留胶囊转为布局约束。
2. 在约束允许的排列中用构建种子选择顺序。需要邻接的单元整体排列；具有先后约束的组执行随机化拓扑选择。
3. 排列完成后一次性计算物理位置，再解全部偏移；超出普通 JMP 距离时只在已证明安全的普通边上加中继。
4. 不用普通中继代替要求直接指向 `TFORCALL` 的目标；方向和取指约束优先于随机性。

**不变量**：逻辑 CFG 不变；所有附加字、跳过对、原生 fall-through 和强制取指关系不变。

**降级**：减少洗牌自由度，恢复受约束组的原有相对顺序；仍不能编码则本原型回退。

**验证**：重解码得到的 CFG 与规划图同构，保留端口映射一致；随机种子只影响布局，不影响观察语义。该项对应 László–Kiss 的块重排，只计布局多样性。

### 4.3 直线块切分

**算法步骤**

1. 候选切点必须处于指令组之间，且 top 状态、关闭栈状态和活跃性均已知。
2. 对单入口单出口直线区域，估计新增 case 的调度成本与数据流接入价值。优先选择能接入运行期数据、位于入口/汇聚点附近的冷或中温站点。
3. 在切点建立新的逻辑边，重新分析活跃性并分配控制包槽位。不能因为分裂前有槽位就假设分裂后仍安全。
4. 热循环头可以放低成本更新；表构造、图谓词、深层 dispatcher 和大量克隆不得放入热循环。无 profile 时以 SCC、自然循环深度和保守估计判热。

**不变量**：原指令顺序与次数不变，新边只增加有限管理步骤。

**降级**：撤销该切点；没有足够有效候选时保留原块，不能为凑 case 数量切开原子单元。

**验证**：局部顺序模拟、每切点槽位验证、热路径额外成本预算。对应 OLLVM SplitBasicBlocks 和 NOP-RL 的站点优先思想；新增指令数不作为效力指标。

## 5. state 经表中转

### 5.1 可行算法及别名作用

**算法步骤**

1. 先证明允许新增私有分配，且分配对原程序可观察 GC/终结器/内存失败行为无影响，或已有运行环境契约明确覆盖。该证明不存在时，本特性默认不可用。
2. 在低频位置创建一个或少量普通强引用私有表。不设元表，不使用弱表，不写 `_ENV`、原 upvalue 或原程序可达对象。
3. 用已证明为合法整数且彼此不冲突的运行期槽键，存放命名空间 token、局部 token 和必要上下文。禁止 nil/NaN 键；不使用 `#` 或 `pairs/next` 推导调度顺序。
4. 建立两个以上表引用别名，在等价路线中选择读写别名。写入后销毁寄存器中的规范 state 副本，让后续分派必须从表读取。
5. 必要时在两私有表之间选择一个保存控制包，但必须携带能唯一确定实际表的安全上下文；不得在读取失败后用默认 state 补齐。
6. 表访问仅使用目标版本原生 opcode；因私有表无元表而证明不会额外调用元方法。扩容和 GC 仍需单独证明，不能与“无元方法”混为一谈。
7. 优先将表生命周期限制在一个冷的管理区域。跨原块长驻的表根只有通过整个生命周期的调用破坏区和 GC 根证明后才允许。

动态表与别名让不建模堆的分析器失去单寄存器追踪能力，符合 D810 指出的别名盲区。但 `T[k]=s; ...; s=T[k]` 且别名显然时可被 store-forwarding 消除；本项只在别名/内存 SSA 攻击后仍有测得收益时保留。

### 5.2 寄存器和栈安全

**不变量**

- `r ≥ 原 maxstacksize` 不等于安全；扩大 `maxstacksize` 也不自动保护寄存器内容。
- 槽位在每个使用点位于可合法访问的帧范围，且在相关 GC 安全点确实作为根存活。
- 任何跨 CALL 的私有值必须避开 callee 实际可覆盖区。固定参数 CALL 的保守充分条件通常是位于调用基址下方且不冲突；最终判定以该 VM 调用模型为准。
- C 被调函数可使用至少 20 个临时栈槽，且可进一步申请空间；20 是必须覆盖的对抗用例，不是允许假定的最大破坏范围。返回不清空上方栈槽，不能靠旧值“似乎还在”维持 state。
- `CALL B=0/C=0`、`RETURN B=0`、`SETLIST B=0`、各版本开放 VARARG 的 top 生产消费链不受注入影响。
- table 根和全部必须存活的别名均被正确保活；死亡别名没有继续被读取。

**失败时降级策略**

分配透明性失败、table 根不能安全存活、别名优化后没有收益、热路径超预算：关闭表模式，回到寄存器控制包。不得把控制状态改放全局变量、`_ENV`、用户表或未经证明的新 upvalue 来绕过槽位不足。

**验证判据**

做逃逸分析、内存读写匹配、别名关系与唯一后继证明；加入强制 GC、栈扩容、C 函数临时压栈及 yield/resume 差分。对比开启/关闭内存建模的攻击器，单独测量表模式的增量收益和分配成本。若资源相关观察属于契约，必须验证相应观察，不能只比返回值。

## 6. 不透明谓词族与自动验证回路

### 6.1 模板契约与实例生成

每个模板必须携带：输入类型与范围、目标整数位宽、参数约束、预期真值或路径关系、读写集合、可能副作用、cost/resilience/stealth 分类、证明方法和版本适配条件。

**算法步骤**

1. 由可信表达式/关系规格生成模板，禁止把手写 Lua 文本当作模板真值的唯一来源。
2. 可用族分为：
   - **整数同余族**：例如 `x(x+1)` 的低位为零。必须在目标位宽模算术上证明；只能当低成本噪声。
   - **整数非平方族**：例如 `7y²−1≠x²`。若使用低位/模 8 证明，应明确目标整数语义；不能把无限精度定理直接套给浮点表达式。它可被定理证明器处理，不是主要强度。
   - **程序相关关系族**：利用原程序已经建立的范围、分支关系或两份相关值；不重复执行会触发元方法的原比较。证明需要路径上下文，不是单独证明一个常量表达式。
   - **私有结构关系族**：沿受运行期选择影响的私有别名/对象关系计算谓词。受第 5 节分配与逃逸限制；简单自比较和显式恒等别名不合格。
   - **候选图关系族**：k-clique 不透明常量等与代数化简不同的方向。默认关闭，先验证候选构造和关系保持，再测专门图化简攻击，不能把一般 clique 问题的 NP 难性直接嫁接到固定小实例。
3. 每站点使用 `(原型构建标识、语义位置、用途、实例序号)` 形成唯一站点标识。该标识只在构建记录中使用，不写成明显运行期标签。
4. 对模板族、参数、表达式结构、输入来源、极性、出口布局做有约束实例化。每次实例化后重新验证，不认为“同模板”意味着参数总安全。
5. 维护原始形态签名和经过统一规范化后的签名。若两个站点只差寄存器名、交换次序或无意义常量扰动，不能算不同的有效实例。
6. 参数空间耗尽或签名重复时重采样；达到有界重试上限后跳过该站点或降低多样性等级。有限空间不能承诺无限站点唯一。
7. 站点数远大于模板数时仍要求族级覆盖、结构组合及输入来源变化；站点唯一不等于抗分析，按 LOKI 的白盒模型把模板和算法全部提供给攻击器。
8. 谓词计算结果必须被分支或后续有效控制数据使用。参与计算又抵消的 junk 必须有真实 def-use 链，但能被整体删除的代数抵消仍只计 cost。

### 6.2 GATE-5 回路

**算法步骤**

1. 对每个模板的规格做形式证明：无未定义操作、无非法类型、无异常转换、无意外元方法，且真值/关系符合契约。失败或求解器未知的实例不进入输出。
2. 对小位宽穷举全域；对真实位宽测试 `MIN_INT`、`MAX_INT`、0、±1、±2、各相关模边界、幂次边界及其邻值。
3. 对全族、全部极性、每类参数边界进行分层随机采样；每个模板必须有覆盖计数，不能用总体样本很多掩盖某个模板零覆盖。
4. 分别求值规格、实例表达式、语义 IR 和最终编码后的真实 VM 行为。记录结果、类型、top、寄存器写集、异常及分支方向。
5. 将实例放进真实 `EQ/TEST + JMP` 包装器，再核对两出口。表达式恒真并不能证明包装器没有把极性接反。
6. 做故障注入：改变运算符、系数、符号、比较极性、MM 参数翻转位，确认验证器会拒绝预期的错误变异。永久保存 GATE-5 恒假事故的最小反例和同类邻域。
7. 最终常量加密后再次验证该实例实际执行的数值和极性，防止参数解密类型变化使先前证明失效。

对于候选 k-clique 方向，先离线构造带可验证 clique 见证的有限图，再由运行期置换改变顶点表示，在私有结构上检查对应关系；验证器必须证明置换保留邻接与见证。攻击器同时获得构造规则，并尝试直接恢复见证或传播邻接常量。此流程定义的是候选生成与否证方法，不宣称该简单构造已经复现论文的抗性；若见证仍显式可读或关系立即折叠，候选不得晋级。图构造与关系求值均受冷路径预算限制。

**不变量**

只有带有效前提的已证明实例可输出；预期真值、包装器极性和目标出口三者一致；模板不依赖未初始化值；所有参数变化保留类型与位宽语义。随机采样用于找错，不能替代全域证明。

**失败时降级策略**

单实例失败立即丢弃；发现模板规格或生成器错误则停用整个模板族及依赖它的候选，回放所有历史种子。不能遇到失败就换一个随机种子直到测试碰巧通过。

**验证判据**

全族覆盖率 100%；所有提交实例证明通过；规格/IR/VM/包装器差异为 0；预定义错误变异检测率 100%。线性 MBA、简单同余和定理型谓词单列成本，不计入主要 resilience 得分。禁止 bitwise 与非常量 0/−1 混用的未验证 mixed MBA，禁止随机无验证 MBA。

## 7. pass 执行顺序与可见性契约

### 7.1 执行顺序

采用以下逻辑顺序；“CFF 最后”指最后一个会重建整体 CFG 的 pass，末尾常量处理只有受限展开权：

1. 原始解码、版本语义检查和基础分析。
2. 字符串加密及其必要解密逻辑插入。
3. 直线块切分、块克隆、花指令、跳转间接化/跳板构造。
4. 寄存器重命名及必要的局部名处理；对捕获描述符和原生寄存器窗口做完整验证。
5. 从真实产物重新解码并重建全部分析，不复用过期 CFG 或槽位结论。
6. 唯一 CFF：把已有代码、保留胶囊和新增控制层统一规划、统一编码。
7. 常量加密的受限局部展开、最终位置重定位和终态验证。

不同项内部可存在已有的已验证顺序，但任何改变必须更新依赖图和组合测试。顺序不是通过任意重排寻找“能跑”的排列。

### 7.2 不允许 CFF 拆毁的产物

**算法步骤**

1. 每个前置 pass 提交产物契约：指令所有权、合法入口/出口、内部重定位、活跃寄存器、top/关闭影响、可见副作用、等价性证书。
2. 解密器中依赖动态 top 的调用区域、关闭区域、原生 MM/附加字/跳过对，按原子或保留区域处理。
3. 花指令的计算与抵消构成完整数据流单元；CFF 不能只保留一半，不能在其中借用仍活跃的私有临时值。
4. 已生成的收敛式假分支可以保留其子图，或者经等价验证整体改写；不能因“看着像 junk”自行删除其一臂。
5. 等价克隆按独立语义块处理；陷阱副本必须携带入口不可达证明。缺失证明时拒绝陷阱特性；不能把陷阱副本加入正常 state 域。
6. 已有跳板若要求保留其间接化结构，则整体作为多端口胶囊，由 CFF 只连接外部端口。若胶囊与最终布局冲突，禁用该原型的跳板特性后从快照重建，不能悄悄摊平后仍报告特性生效。
7. 前置 pass 生成的 `_ENV` 访问保留其确切 upvalue 绑定，CFF 自身不借用 `_ENV` 存 state。

### 7.3 常量加密的最后阶段约束

**算法步骤**

1. CFF 输出常量用途清单：业务值、公共算术参数、控制编码参数、跳转/附加字字段、受类型约束的谓词参数。
2. 常量加密只能替换有明确接口的值加载单元，保留对外 def-use、类型、入口、出口、top 和关闭关系。内部可有已经证明的局部分支，但不能引入跨胶囊边或新 dispatcher。
3. 禁止替换 opcode 字段、偏移和 `EXTRAARG` 为“普通加密常量”；它们是编码结构，不是任意可加密值。
4. 所有长度变化由统一最终布局器重算跳转和范围，随后独立解码最终产物。CFF 的局部证书按展开契约组合，不能因“CFF 已测试过”跳过最终检查。
5. 无局部安全槽位或无法保持整数类型时，跳过该常量的加密；不通过新增 CALL、全局函数或未知表访问来勉强解密。

**不变量**

每个 pass 只依赖重新分析的真实输入；所有保留产物在重建后仍满足原契约；最后一个结构性变换仍为 CFF；常量阶段不能破坏 state 的动态来源、类型或不可达证明。

**失败时降级策略**

撤销最小依赖闭包并从对应快照重建。CFF 拒绝不撤销已经独立验证的字符串加密等前置产物；最终常量加密失败可保留 CFF 的已验证未加密参数版本。对不能局部撤销的组合，恢复该原型最近完整验证快照。

**验证判据**

验证单 pass、关键两两交互、全部发布组合和最坏压力组合。被保护胶囊的端口、指令组、有效 use 和陷阱不可达性在最终字节码中全部重验。报告每项实际保留的特性，不能把被后续 pass 消除的特性记为开启。

## 8. 拒绝规则全集与每原型降级

以下是闭世界判定：仅清单内且已建模的语义允许转换；出现新的未知形态，一律归入“未知语义”，不能用默认 opcode 行为补洞。“整体跳过”均指当前原型的 CFF，而非整个 chunk。

| 编号 | 根因类别         | 触发条件                                                         | 处理                                                   |
| ---- | ---------------- | ---------------------------------------------------------------- | ------------------------------------------------------ |
| R01  | 输入无效         | 截断字节码、非法 opcode/索引、非法附加字入口、无法成立的取指结构 | 拒绝该输入作为可转换程序；不能声称原样字节码是安全修复 |
| R02  | 版本模型缺失     | 未锁定 VM 构建、整数/浮点配置未知、5.5 新 opcode 或字段未建模    | 整原型跳过 CFF；保留合法原输入                         |
| R03  | 控制流不闭合     | 目标无法解析，内部入口无法用多端口区域保留，出口漏建             | 整原型跳过                                             |
| R04  | 指令组冲突       | 必须消费/跳过关系与重排要求不可同时满足                          | 扩大保留区域；仍失败则整原型跳过                       |
| R05  | 循环约束失败     | 方向、偏移、原生取指目标或寄存器窗口不能保持                     | 保留循环区域；仍失败则整原型跳过                       |
| R06  | top 不可证明     | 开放结果生产消费链不闭合，注入点 top 未知，保留区域也不能隔离    | 整原型跳过                                             |
| R07  | 存储不足         | 基线所需控制槽位也无法在所有使用点证明安全                       | 整原型跳过；不能盲目增大 maxstack                      |
| R08  | 调用破坏         | 私有长驻值可能被 callee 临时栈覆盖或失去 GC 根                   | 改为短生命周期/撤销表与长驻键；基线仍受影响则跳过      |
| R09  | 关闭/捕获失败    | 5.3 JMP 关闭、TBC/CLOSE、返回关闭、捕获身份或关闭顺序不明        | 保留区域；仍不能证明则跳过                             |
| R10  | 异常/协程失败    | 原元方法、错误、yield/resume、尾调用恢复点无法对应               | 整原型跳过相关 CFF                                     |
| R11  | 观察契约冲突     | 字节码自省、hook/栈布局/物理 PC 等被观察且无兼容契约             | 跳过所有会改变相应观察的变换                           |
| R12  | 新分配不透明     | 表分配影响 GC、终结器或资源错误且无证明/契约                     | 关闭表/图特性；并非自动拒绝无分配 CFF                  |
| R13  | 动态来源不足     | 种子静态恒定、路径上已固定、读取会产生新副作用                   | 降低 state 配置；不授予动态 state 预设资格             |
| R14  | 编码证明失败     | 双射、域分离、范围、有效包闭包或唯一目标不成立                   | 丢弃候选；回退已验证配置                               |
| R15  | 谓词证明失败     | 模板/实例真值未知、整数前提失败、极性不一致                      | 停用实例或模板族；回退依赖候选                         |
| R16  | 前置产物契约缺失 | 陷阱可达性未知、胶囊无端口契约、已有私有寄存器归属不明           | 撤销该前置特性重建；否则跳过当前原型 CFF               |
| R17  | 编码容量不足     | 指令数、寄存器数、常量索引、偏移或 chunk 字段超限                | 降低切分/克隆/布局/dispatcher 数；仍超限则跳过         |
| R18  | 验证未知/失败    | 证明超时、求解器 unknown、重解码不一致、差分反例                 | 不提交；未知不能按成功处理                             |
| R19  | 性能预算失败     | 热循环成本、体积、内存或验证时间超上限                           | 撤销高成本特性；不能降低语义检查强度                   |
| R20  | 对抗或泄漏失败   | 动态依赖被全折叠、明文 case 映射泄漏、承诺收益不存在             | 撤销对应安全等级/预设资格；正确基线可继续输出          |

### 8.1 统一降级算法

**算法步骤**

1. 为每个特性设独立开关和依赖关系；独立开关不意味着不检查依赖。显式关闭依赖时，报告依赖特性不可用，不能偷偷开启被关闭的项。
2. 请求配置先按适用条件过滤，再执行完整验证；失败时撤销产生失败证明义务的最小特性依赖闭包。
3. 一个典型成本降级顺序为：图关系 → 表中转 → 复杂别名/嵌套 → 入度网关/克隆 → 更多切分 → 复杂布局；具体顺序由根因决定，不盲目按固定列表删除。
4. 状态编码或基本边模拟失败时直接丢弃当前候选，重新从快照生成已验证基线，不能保留未知的部分控制层。
5. 基线仍失败时返回 `UNCHANGED_CFF(reason)`；成功返回 `APPLIED(actual_features, proof_manifest)`；无效输入返回 `INPUT_REJECTED(reason)`。
6. 对原型分别记录请求特性、实际特性、保留原生边、拒绝原因、失败阶段。子原型能通过时可以转换，即使父原型保持不变；跨原型接口必须保持。

**不变量**：提交单位为整个原型事务；不输出半改写原型；拒绝分母固定，不能通过跳过难例提高成功率。

**验证判据**：所有拒绝均有稳定根因码；对每个根因有合成测试；父/子原型独立回退测试不产生描述符悬空。覆盖率同时按原型、指令、原始边、循环边和业务热度计算。

## 9. 验证矩阵、发布闸门与论文对齐

### 9.1 多维矩阵

**算法步骤**

1. 固定矩阵的 VM 轴：5.3、5.4、5.5 的实际支持构建；每个构建锁定源码摘要、整数位宽、数值配置和字节码格式。不同小版本或定制 VM 不能未经验证共享绿色状态。
2. 固定模式轴：原程序、唯一内核基线、每个特性单独启用、关键两两组合、每个发布预设、全开压力模式、每条降级路径。
3. 固定语义轴：
   - 比较全部极性、RK/寄存器/立即数形式、TESTSET 条件赋值、跳过指令、MM 成功和回退。
   - 整数/浮点数值 for：正负步长、空循环、一步、边界、溢出附近、无效参数、控制变量相关行为；完全依照各版本原 VM。
   - 泛型 for：0/多结果、关闭变量、迭代器错误、yield 和嵌套；5.5 的窗口变化单独覆盖。
   - 嵌套闭包、捕获、5.3 `JMP A≠0`、TBC/CLOSE、返回和错误中的关闭次序。
   - 所有开放 top 组合、nil 空洞、多返回值、开放 VARARG、尾调用、5.5 新可变参数指令。
   - 原型接近寄存器/常量/偏移边界；多端口区域、不可达但合法代码、非常规合法字节码。
   - C 函数至少压入 20 个临时值、额外申请更多槽位、栈移动、不清空临时区；不能只用 Lua 被调函数验证槽位安全。
   - 强制 GC、可观察终结器、元方法重入、协程 resume、错误对象和可见堆修改。
4. 固定随机轴：构建种子、程序生成种子、输入种子、参数种子；全部可复现。保留训练/开发语料与隐藏评估语料，防止 fixture 特判。
5. 对同一 VM、同一输入、相同外部事件执行原版与混淆版，比较规范化观察轨迹；带身份的对象按保持别名关系的对应映射比较，不直接比地址。
6. 浮点值、NaN、负零、整数/浮点子类型和错误对象按事先定义的观察契约处理；不得为了通过测试才扩大容差。行号/栈轨迹差异只有在契约预先允许且有映射时才可规范化。

### 9.2 翻译验证与 fuzzing 的组合

**算法步骤**

1. 借鉴 translation validation：每个转换结果都带源单元到目标区域的映射、控制包关系、活跃值关系、top/关闭关系及终止排名函数。
2. 独立验证器从最终编码重新解码，检查映射，不直接相信 emitter 的内部 CFG。使用与 emitter 不同的参考解释路径及 VM 真值表用例，降低“生成器和验证器共享同一错误”的风险；语义清单自身也需要对真实 VM 做一致性检查。
3. 原复杂 opcode 尽量原样保留，用“相同操作、相同前态、相同调用点”进行局部模拟；新控制逻辑限制在易证明的整数、真值测试和受限私有内存操作中。
4. 将每条原边证明组合成循环不变量和全原型有限停顿模拟。证明不了的堆/元方法/协程情形扩大原样保留区域或拒绝，不靠有限展开假装覆盖所有循环。
5. 类似 Alive2 的有界检查用于快速找错，不能将有界通过写成无界等价证明。位向量等式、别名契约和管理图终止分别检查。
6. fuzzing 分为合法字节码生成、Lua 源级生成、保结构字节码变异、特性参数变异；先通过独立合法性筛选，再进入差分。
7. 反例按保持原子单元/循环约束的方式缩减，归档到永久回归集；记录原型粒度根因及涉及的 pass 组合。

### 9.3 反编译与反平坦化对抗

**算法步骤**

1. 白盒提供算法、模板、编码规则和预设；隐藏构建种子只能作为多样性，不能成为唯一防线。
2. 攻击器至少包括：
   - D810 风格的比较链/state 常量识别及局部符号恢复。
   - Lebedev 约束下的单控制值、连续 dispatcher 恢复，以及放宽这些假设后的对照版本。
   - CaDeCFF 思路的数据流/语义恢复；不能只找 CFG 形状。
   - 常量传播、死代码删除、代数/MBA 化简、表达式归一化与 e-graph 类化简。
   - 内存 SSA、别名传播、store-forwarding、私有表标量替换。
   - 动态轨迹、污点和符号/合取执行联合恢复；区分单路径恢复和全 CFG 恢复。
3. 对不能直接读取 Lua 的论文工具，使用经验证的 Lua IR 适配器或复现其核心攻击条件；报告适配误差和支持范围。不能把“工具不支持 Lua 5.5”算成保护成功。
4. 反编译器的成功条件是得到保持原行为的可执行或可验证表示，不是界面是否报错。语法解析崩溃不能单独作为 resilience 指标。
5. 做消融实验：保持版本、语料、构建预算和攻击预算相同，分别关闭动态 state、命名空间、段副作用、表别名、入度和布局，测增量贡献。

推荐指标：真实边恢复 precision/recall、后继语义恢复率、成功重建并通过差分的比例、完成时间/求解器工作量、残余不确定边比例、攻击覆盖率。超时按删失数据报告；不把超时或工具崩溃自动记为不可破解。

### 9.4 泄漏审计

**算法步骤**

1. 审计最终常量池：无专用明文 case ID 表、无每块一个高熵 32 位 state 常量列表、无生产环境可达的构建映射或 proof manifest。
2. 审计数据流：运行期种子未被最终 pass 固化；state 表读取有实际 use；新增垃圾计算无“结果无人用”；慢速解码路径没有新增明文映射泄漏。
3. 审计模板：无 `nil==nil`、`1==1` 或等价显式恒等测试；无单模板覆盖全部站点；无把 7y² 关系、线性 MBA 或不可达循环计为主要强度。
4. 审计布局与元数据：调试名、upvalue 名、旁路常量、序列化顺序不能直接标出真实/垃圾块或明文目标表。维护信息保存在非运行期构建记录中。
5. 不把“没有可见 case 常量”解释为“CFG 不泄漏”；指令序列、可逆关系和动态轨迹仍可暴露控制流，必须继续做语义攻击。

### 9.5 闸门定义与回退数字

每个发布预设绑定固定语料、固定攻击预算、覆盖率分母、性能预算与上一版已验证基线。预算可由产品设定，但必须在评估前冻结；下列零容忍项不可配置放宽。

| 闸门               | 验收数字/条件                                                                | 哪个数字恶化必须回退                                         |
| ------------------ | ---------------------------------------------------------------------------- | ------------------------------------------------------------ |
| GATE-0 结构与版本  | 提交产物非法指令组、错目标、错方向、错字段均为 0                             | 任一项从 0 增加：拒绝候选并停用相关新特性                    |
| GATE-1 逐原型证明  | 提交原型所需证明覆盖率 100%，unknown 数 0                                    | 覆盖率下降或 unknown 增加：该原型不提交                      |
| GATE-2 语义差分    | 可判定测试的观察不一致、额外错误、错返回个数均为 0；所有要求单元完成         | 出现 1 个反例即阻断发布；超时/未执行项不能当通过             |
| GATE-3 栈/top/关闭 | 槽位安全覆盖率 100%，越界/被覆盖长驻值/关闭失配为 0                          | 任一证明缺失或失配：回退涉及配置                             |
| GATE-4 控制包      | 双射、有效包闭包、唯一命中、有限终止全部成立；安全网命中 0                   | 任一反例或可达终端 RETURN：拒绝候选                          |
| GATE-5 谓词        | 全族覆盖率 100%，实例证明 100%，规格/IR/VM/极性差异 0，指定错误变异检测 100% | 任一比例下降或差异增加：停用模板族并回放历史种子             |
| GATE-6 覆盖与降级  | 固定必支持语料覆盖不低于既有基线；根因记录率 100%                            | 覆盖下降无预先说明或拒绝原因缺失：阻断新预设；不得删除难例   |
| GATE-7 性能        | 每版本/模式 p95 延迟、热循环成本、内存、体积不超过预设预算                   | 任一分层预算越界：撤销高成本特性或降低预设                   |
| GATE-8 对抗收益    | 固定攻击集合下达到预先登记的最小收益 δ；隐藏语料的置信区间支持增量收益       | 边恢复率/重建成功率显著升高，或收益低于 δ：回退安全等级/预设 |
| GATE-9 泄漏        | 禁止模式泄漏项 0；动态 state 合格站点比例达到预设承诺                        | 出现禁止泄漏，或动态依赖比例下降：撤销对应特性资格           |
| GATE-10 组合与复现 | 所有发布组合完成率 100%；同种子配置输出及判据可复现                          | 组合缺测、不可复现、最终常量阶段破坏证书：阻断发布           |

GATE-8 中“恢复率越低越好”“耗时越高越好”必须与攻击预算及成功条件一起报告。不能用把程序扩大十倍后的工具超时掩盖热路径预算失败。δ 是工程验收门槛，不是论文保证；评估前没有设定 δ 的方向只能报告实验结果，不能宣称进入安全预设。

正确性闸门失败时回退代码产物；只有对抗收益失败时，可以保留语义正确的基线产物，但必须降低声明的保护等级。若发布后发现错误，立即停用相关特性组合并按根因及构建记录重建受影响原型，不能仅将默认值改回去而保留已知错误产物。

### 9.6 开关和预设晋级

**算法步骤**

1. 保留已验证 `cff.baseline` 的现有默认状态；新增 `state.runtime`、`state.namespaces`、`dispatch.segmented`、`dispatch.multiple`、`dispatch.nested`、`dispatch.effects`、`indegree`、`layout`、`split`、`state.table`、各谓词族均独立登记并默认关闭。
2. 每个开关分别具备适用条件、依赖、证明义务、成本预算和实际启用计数。不能只提供一个“强混淆”总开关遮蔽失败来源。
3. 先过单特性矩阵，再过依赖组合和整预设矩阵，最后进入发布预设。三版本都通过才称跨版本预设；部分版本通过只能在对应版本开放。
4. 基线允许作为兼容配置继续使用，但不能命名为“论文级完整版”。完整版至少需要已验证的运行期数据依赖、多 dispatcher/分段管理及有 use 的控制更新；表与图方向仍是可选项。
5. 如果某个原型只满足基线，就明确报告基线；如果无可安全转换边，报告未应用，不能把原样输出记入成功 CFF 覆盖率。

**不变量**：所有提交结果先满足语义闸门，再评价对抗收益；所有统计使用预先冻结的分母、预算和观察契约；任何一层的未知不能在上一层被记为成功。

**失败时降级策略**：按闸门表回退产物、模板族、特性组合或声明等级；保留最小反例与实际配置，不以重抽种子、跳过困难样本或放宽比较器消除失败。

**验证判据**：发布报告可从锁定的 VM、语料、种子和配置重新产生；语义零容忍项全部为零，证明和必要矩阵覆盖全部完成，性能与对抗收益分别满足冻结门槛。
