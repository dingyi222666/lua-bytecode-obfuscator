# Lua Cloak：兼容冻结 CFF 契约的 VM 化保护算法设计

本文只规定算法、状态关系、证明义务、降级和验证；不提供实现代码。目标解释器为官方 Lua **5.3.6、5.4.6、5.5.1**，分别生成各自可直接加载的 chunk，不承诺一份二进制跨版本加载。第一层沿用任务书附录 A，以下不修改其语义清单、原子单元、观察契约、拒绝规则或闸门。章节 4.1–4.8 与任务书逐项对应。

本文中的“候选 resilience”仅表示值得对指定攻击器测量的方向；通过正确性验证不意味着通过对抗验证。新增特性默认关闭；现有 VM 基线是同一实现的兼容配置，不能把已有差分通过升级为未经证明的完整语义支持。“定制工具及人日级投入”是待测目标，不是保证。

## 1. 统一定义与不可回避的边界

### 1.1 状态、观察与证明对象

原程序状态记为 `L=(原型, pc, R, top, U, H, 关闭栈, 调用/协程续体)`。VM 状态记为 `X=(子程序, 区域, 微步, VReg, VTop, Cells, VFrames, Pending, Ctx, Payload)`；宿主 Lua 状态另记 `Host`。原程序的 CFF 控制包是 `VReg/Cells` 中的**被解释程序数据**，不得与解释器自己的 `Ctx` 合并。各调用帧、协程和嵌套解释器的私有状态彼此分离。

`Obs` 完全继承附录 A：结果个数与值、可达堆/upvalue、I/O、错误对象、元方法、关闭与 yield/resume 顺序。身份比较采用保持别名和函数相等关系的映射，不按地址比较；整数/浮点子类型、负零、可观察 NaN 行为必须保留。源程序不终止时要求有限观察前缀和分歧对应。

VM 模拟关系 `Rvm(L,X,Host)` 必须包含：源活值映射、虚拟 top、共享捕获单元身份、源堆身份、待执行副作用位置、关闭链和协程续体；目标额外步骤在每个源步骤之间有限终止。不能只证明最终返回值相等。

### 1.2 六项否定结论

1. **不存在从公开确定性材料凭空产生秘密的算法。** 构建 seed、密钥流位置、私有计数本身不满足附录 A“运行期不可折叠量”的资格。没有输入依赖就报告静态可推导；有输入依赖也不等于秘密。
2. **“全静态可恢复面为空”的无条件证明不成立。** 攻击者可执行公开生成器、解释器或做全程序解释。本文只定义可执行的禁止泄漏清单与固定预算下的恢复指标，拒绝把有限审计写成不可恢复证明。
3. **有限 opcode、有限位宽上下文不存在数学上不可枚举的状态空间。** 可以测预算内不可穷举，不能宣称不可枚举。单次 gadget 失效也不代表可快照、多次追踪的攻击失效。
4. **超指令长度不是未知 opcode 数。** 一个长 handler 仍可能被一次输入输出学习，甚至减少攻击者需要识别的槽位。只有经实测仍不能分离的语义假设联合增长，才可能改变恢复曲线。
5. **handler 入口不天然属于温路径。** 循环中每次执行的入口与 dispatch 同热；画像频率决定预算。额外分配也会改变 GC、弱表、终结器、资源错误，不能以“私有”免除证明。
6. **纯 Lua 解释器不自动完整模拟 Lua 本身。** 精确原生错误文字、调试栈、开放 upvalue 生命周期、TBC、任意 yield、分配时机均有边界。无已有环境契约或兼容证明的情形逐原型拒绝，不能为提高覆盖而悄悄缩小 Obs。

### 1.3 统一规划与成本算法

**目标与攻击模型。** 用同一语义核提供兼容配置与候选保护配置；以 LuaHunt 式变异、可读取内部状态的白盒快照攻击和跨样本迁移攻击共同评估。opcode 重排、字节加密、布局、命名、线性 MBA 单独只计 cost。

**成本档位与放置位置。** L 为每步有界的整数操作、索引和固定大小上下文更新；M 为小区域入口的格式转换、有限模板分派；H 为图构建、全区域转码、重型校验、嵌套 VM。L 仍须测热循环预算；M/H 只用于画像证明足够低频的位置。无画像时按循环嵌套和调用 SCC 保守估计，递归入口不算冷路径。

**算法步骤。** 冻结预算 `B=(各版本慢化、热循环附加成本、体积、峰值内存、分配数、验证时限、攻击预算)`；成本按 `Σ 站点频率×单次成本`、调用嵌套及两层 CFF 的交叉影响计算。每个开关登记前提、依赖、proof obligations、actual_features、根因和成本档。先选可证明配置，再优化对抗收益/成本；不以失败后重抽随机种子代替修复。

**不变量。** 一个解码器接口、一个 VM 语义 IR、一个规划器、版本化 emitter。原生 Lua 解码和私有载荷解码是同一接口的格式适配器，不是两套语义实现。提交的每个原型拥有唯一实际配置。

**失败时降级策略。** 撤销导致义务失败的最小依赖闭包，从快照重建；正确性失败回退产物，对抗失败回退保护等级。可用纯 CFF 产物保留，不能宣称 VM 已应用。

**验证判据。** 配置、预算、覆盖分母、攻击成功定义在评测前冻结；所有新开关有单特性、依赖组合和回退测试。

**论文依据与红线自检。** Collberg 的 cost/resilience/stealth、LOKI 白盒方法、附录 A 的 translation validation；不把体积和随机种子当强度。

## 4.1 Lifter 与程序模型

### 4.1.1 输入契约与结构保留

**目标与攻击模型。** 保留 CFF 已建立的数据流障碍，避免 lifter 自行去平坦化。此项是 potency 保持，不独立宣称提高 LuaHunt 的指数。

**成本档位与放置位置。** 主要为离线成本；运行期保持源 CFF 已付出的开销，不无条件再嵌套一层控制包。

**算法步骤。**

1. 输入为真实 CFF 字节码、匹配其摘要的离线证书，以及 VM 构建清单。独立重解码；证书仅提供候选映射，不能替代检查。
2. 建立映射：原子单元→带内部微步和合法端口的 IR 区域；循环约束组→版本化循环语义及其出口；动态 top 无注入区→不可跨越的效果区域；控制包字段→独立逻辑值/内存位置；谓词站点→带规格与 use 的谓词节点；关闭/yield 点→效果屏障。
3. 指令消费闭包整体 lift。比较/JMP 的两出口、TESTSET 的条件写入、MM 尾的成功跳过和失败调用、EXTRAARG 的消费都在一个语义区域内表达。合法多端口不得被改成单入口；无法表达则 RV-03。
4. 只做地址重定位、表示转换和经过证明的局部调度。禁止沿已知 CFF state 做跨块常量传播、删除 dispatcher 副作用、把谓词后的管理图折回原 CFG。源 CFF 管理节点即使可被优化，也必须作为被保护程序语义保留。
5. 每个原 CFF 节点记录目标 IR 覆盖集合和出口映射；融合可跨多个节点，但须保留其顺序、逻辑状态更新和中间可观察点的精化映射。证明内部保留不等于对攻击者输出该映射。

**不变量。** 原 CFF 控制包和 dispatcher 有效 use 不丢失；源端口一一对应；VM 私有状态更新不回写源控制包；离线证明元数据不进入生产载荷。

**失败时降级策略。** 先撤销融合、表示变换或调度；仍不能建立映射则该原型 RV-03/04 回退纯 CFF。

**验证判据。** 源单元/端口覆盖 100%；闭包与有效 use 重验 100%；在 VM 语义展开视图上复核附录 A GATE-4/5；用故意删除一个 CFF 管理更新的变异确认验证器能发现。

**论文依据与红线自检。** CaDeCFF、D810、Lebedev 说明结构并非全部；本步骤不靠“lift 后看不出 CFF”自证收益。

### 4.1.2 不可变语义清单 V_vm

**目标与攻击模型。** 消除版本和操作数方向错译；此项只保障正确性，不增加攻击成本。

**成本档位与放置位置。** 离线 H；运行期仅支付相应原语义。

**算法步骤。** 对每个 `版本×opcode×操作数形式` 建记录：源码摘要与分支位置、位偏移/宽度、符号扩展、RK/k/vB/vC、立即数偏置、隐式读写、取指、top、关闭、元方法、错误、yield、源原子组和目标宏语义。字段布局从精确 `lopcodes.h` 与模式表建立；行为依据 `lvm.c` 及其调用的对象/调用/元方法例程锁定。不能从注释自动“证明”行为。每条实际发射的 handler 微操作反向列出依赖记录，缺一即拒绝。生成完整核对表的方法和关键行见 §4.7.1。

**不变量。** 无“默认按 5.4”分支；同名 opcode 不构成跨版本同义证据；源整数是该构建位宽的模运算，宿主辅助计算不误用浮点近似。

**失败时降级策略。** RV-01/02；未实现语义的原型退出 VM 选择，不能把未知指令当 NOP 或调用通用 ADD 猜测。

**验证判据。** 发射覆盖对应的语义记录为 100%；SETI、SETLIST 及 5.5 ivABC 字段变异必须全部被杀死；真实三版本解释器作为独立参照。

**论文依据与红线自检。** Necula 翻译验证与附录 A 清单 V；测试只能找错，不能替代缺失语义。

### 4.1.3 嵌套原型、闭包与调用约定

**目标与攻击模型。** 建立可组合的多程序语义。复杂调用不是免费强度；需在 LuaGadget 中纳入跨调用语义恢复，不能以攻击器不支持闭包记成功。

**成本档位与放置位置。** 帧/闭包创建 M，调用边 L/M；递归按热路径计费。

**算法步骤。**

1. 定义值序列为 `Seq=(n, slot[1..n])`，nil 可占位；所有参数、varargs、返回、yield 和 resume 均携带显式 n。不得用表长度、最后非 nil 索引或 truthiness 推断个数。
2. 虚拟寄存器值保持原 Lua 值身份，辅助容器禁止元表和逃逸。建立帧时按源固定参数数目复制参数并补 nil，额外参数以显式长度保存；其他源可读槽按锁定 VM 初始化规则建模，非法/未知的未初始化读不得猜值。`VTop` 是独立的排他上界；`CALL B=0` 的参数范围为 `[A+1,VTop)`，固定 B 取 B−1 个参数；固定 C 接收 C−1 个结果并按语义补 nil，C=0 以实际 n 设置 `VTop=A+n`。`RETURN B=0` 返回 `[A,VTop)`；其余 RETURN/VARARG 依版本记录处理，不借宿主 `L->top` 保存虚拟 top。
3. 虚拟闭包记录子程序及 `CellRef[]`；同一源开放 upvalue 必须共享一个 cell。源寄存器被关闭后，旧闭包仍指向旧 cell；下一次进入作用域可产生新 cell，不能只按寄存器编号永久复用。
4. 对 VM→VM 调用，显式帧保存续体、Ctx、VTop 和结果接收协议。尾调用在证明关闭顺序后替换逻辑帧，不能让尾递归线性增长私有帧。VM→原生调用使用经验证的参数/结果适配器；返回序列显式携带长度。原生→VM 用真实 Lua 函数 wrapper，捕获固定解释器环境和对应 cell 引用。
5. 同一虚拟闭包向外物化 wrapper 时保持身份；不能每次读取都新建函数。5.3 闭包缓存对函数相等可能可见，按源码条件复现缓存/复用，或证明该身份不可观察；否则 RV-06。
6. 混合原生/VM upvalue：无捕获或被证明不可变的共享值优先支持；可变共享单元只有现有注入机制能让双方实际访问**同一个原生 upvalue**时才支持。访问器须由真实 luac 生成并正确捕获原槽位，原生部分保留该 cell，VM 经访问器读写；关闭后身份仍一致。禁止把值复制到表里冒充共享 upvalue。无法在冻结的输入接口中安置已验证桥接时，拒绝相关 VM 边界，不事后改写第一层 CFG。
7. 宿主可自然跨 yield 的 Lua 调用栈优先保留。调用前把 `Pending=(源操作,阶段,结果接收位置)` 和帧状态安置为可恢复状态；恢复后只提交一次结果，不能重做已发生的元方法/I/O。禁止每条 CALL 外套不必要的 pcall。任意协程边界、原生不可 yield 边界或尾调用关系无证明时 RV-08。
8. 错误对象自然传播，禁止转字符串和吞错；对可重抛对象需证明对象身份和关闭序列。原生类型错误可能含源名称/位置，纯 Lua handler 产生的新报错通常不等价；优先证明不会触发，否则只能使用经验证的精确错误桥接或 RV-09。TBC/CLOSE 不用普通表删除、finally 模拟；只有版本化关闭桥接验证后才支持。
9. 返回、尾调用替换和错误退出后，按证明过的生命周期撤销帧/暂存结果的私有强引用，保留逃逸闭包必须共享的 cells。弱表、终结器或资源行为可能观察额外引用和分配，因此需沿用既有观察契约或证明其透明；不能以“值已无 use”直接证明额外 GC 根不可观察。

**不变量。** 序列长度不因 nil 改变；每个源副作用恰好发生一次；upvalue 身份、关闭和栈续体可对应；私有对象始终为 GC 根，callee 可申请超过 20 个临时槽位仍安全。

**失败时降级策略。** 分别使用 RV-05/06/07/08/09/10。收缩到有证书的原生/VM接口；接口不能保留则该原型保持纯 CFF。不能通过返回少一个值“兼容”未知调用约定。

**验证判据。** 0/1/多结果、头/中/尾 nil、额外参数、嵌套 vararg、多层调用、尾递归、交错协程、元方法 yield/错误、可变共享捕获和重复闭包相等逐项差分。永久回归包含“子程序返回 `a,nil,b,nil` 后外层调用收到恰好四个参数”，检查调用轨迹和返回个数而非只看 print 文本。

**论文依据与红线自检。** 组合模拟与附录 A Obs/top/关闭契约；复杂调用未验证时不得按“Lua 函数互调天然安全”放行。

### 4.1.4 哪些原型进入 VM

**目标与攻击模型。** 在固定覆盖分母和性能预算内选择有潜在收益的原型；禁止只留难攻击样本制造 LuaHunt 成功率下降。

**成本档位与放置位置。** 离线画像/优化 M；程序入口可承担初始化 H，热循环只允许已定额 L。

**算法步骤。** 为所有原型建语义能力、调用/捕获依赖、循环热度和预算表；先做可证明性筛选，再比较 VM 与纯 CFF 的成本。选择单位默认为整原型；可选区域 VM 必须有独立入口/出口 ABI 证书，否则不实施。VM 子原型替换保持父原型可见的参数、upvalue 描述符和返回 ABI；跨边界共享关系依 §4.1.3 检查。某接口失败只撤销依赖该接口的候选，不无关连坐整 chunk。即使多个原型必须共同发布桥接，也逐个记录判定和根因，最后对引用关系原子提交。

**不变量。** 分母包括全部输入原型及难例；`selected`、`applied`、`refused`、`pure_cff` 分开；库函数或热循环不因源码名字被特殊处理。

**失败时降级策略。** RV-11/18/23 或具体接口根因；原型退纯 CFF，其他独立原型继续。

**验证判据。** 父 VM/子原生、父原生/子 VM、双方 VM、双方回退的 ABI 矩阵；原型/指令/边/热度覆盖分别报告。

**论文依据与红线自检。** Collberg 嵌套成本、NOP-RL 位置原则；位置价值不能豁免成本闸门。

## 4.2 ISA：从 opcode 命名转向联合语义恢复

### 4.2.1 超指令合成

**目标与攻击模型。** 候选 resilience：增大一次独立语义分割所需恢复的联合关系。对手可观察输入/输出、变异载荷、做动态切片与综合，允许把一个超指令整体学习。

**成本档位与放置位置。** 合成与证明离线 H；融合有机会减少热 dispatch，入口解码 L/M。不得为增加融合长度复制热计算。

**算法步骤。**

1. 在已 lift 的效果 IR 上采集合法原子单元序列和数据依赖子图；按频率、共享中间值、分支相关性、调用/关闭屏障、代码增长排序。默认只融合单入口、有限出口且效果序可证的区域。
2. 构造宏语义 `M=(输入活值,内部状态转移,有序效果,输出活值,出口)`。超指令应包含多个真实依赖步骤；单纯串联互不相关的 ADD 不算联合困难。
3. 用预算约束的覆盖规划选宏集合；构建种子选择不同**合法分解**、融合窗口和宏集合。未覆盖部分使用同一 IR 的基础宏，不另开旧解释器；不能因此把主要程序仍为 1:1 ISA 却标为新 ISA。
4. 保留错误/yield 微步；有外部入口就停止融合或提供证明过的多端口宏。融合不能让后半段在前半段已抛错后仍执行。类型未知、元方法可能调用时禁止代数重排。
5. 用联合未知量 h 建攻击模型：h 指一个有效 gadget 中仍需联合求解的语义选择数，不是源指令条数；第 i 项候选数为 dᵢ。独立盲枚举上界为 `∏dᵢ`，可分离恢复常接近 `Σdᵢ`，有 trace/综合时可能更低。不得把乘积写成攻击下界。
6. 生成 h、依赖宽度和宏长度独立变化的测试组，匹配功能/大小/预算；分别给攻击器边界 oracle、真实快照和正常黑盒入口。测完成语义恢复所需有效查询、求解时间、人工适配时间，拟合指数/多项式/分段模型并报告置信区间；h 不能由设计者自行宣称。

**不变量。** 宏是精化的原语义序列；源 CFF 管理效果保持；融合不会新增或丢失观察。

**失败时降级策略。** 不可证明则拆回更小宏；只有 cost 收益则标注 cost；达不到发布预设最小复合语义覆盖率则降保护等级，不强凑宏。

**验证判据。** 宏规格与所有出口模拟 100%；宏长度/有效 h/恢复耗时分别报告；相同攻击器学习整体宏也计攻击成功。

**论文依据与红线自检。** LuaHunt 的 gadget 测试、LOKI 的语义组合思想；“90 秒/用例”仅作题设基线，须本环境复测，不外推为普遍定律。

### 4.2.2 上下文相关的多态 ISA

**目标与攻击模型。** 候选 resilience：同一字节 opcode 的含义不能仅靠一个脱离状态的探针确定。对手可恢复/替换上下文、重复快照、先执行合法前缀，因此只声称使单 opcode oracle 不充分。

**成本档位与放置位置。** 每宏有限上下文更新 L；多版本载荷和区域重编码 M/H，仅在允许的低频入口。

**算法步骤。**

1. 定义有界上下文 `C=(格式模式,区域表示,continuation阶段,流位置,路径摘要)`，宽度和回绕显式指定。每调用帧独有；不得使用时间、随机库或外部副作用获取熵。
2. 同一物理 opcode o 在不同 C 下选择不同微程序 `H[o,C]`。编译器为每个合法入口上下文选择匹配的载荷变体；运行期派生的模式必须从已生成的完整变体集合选择，不能让一份固定密文在任意 key 下凭空解出相同指令。
3. 对表示变换 T，要求 `DecodeState_C′(H[o,C](EncodeState_C(s))) = M(s)`。若只做 opcode 置换或寄存器共轭，老实计 cost；候选 resilience 需包含多步 continuation、共享中间量或上下文相关的不同宏分解，并接受整体宏恢复攻击。
4. 模式更新 `C′=F(C,已执行宏,已提交出口,私有中间量)` 必须有全路径证书。效果操作前记 pending 阶段，完成后推进；resume 不重复推进。计数按指定位宽回绕，不因长循环溢出进入未定义模式。
5. 控制包/格式的运行期输入依赖如来自附录 A 的 K，只读取已有私有表示；证明存在两个合法输入使实际编码不同。没有这类证据时标记“执行状态相关、静态可推导”，不授予动态种子资格。

**不变量。** 每个有效 `(站点,C)` 唯一解出合法宏；所有可达模式闭合；相同输入及环境事件确定复现。不同 C 的多态不能改变逻辑程序。

**失败时降级策略。** 撤销模式数或 continuation 拆分；回固定宏 ISA。模式不可证明则 RV-12/13，不允许默认选第一个 handler。

**验证判据。** 有限控制模式穷举；数据域证明加边界/随机测试；相同 o 在真实可达不同 C 中确有不同原始转移；攻击器获 C oracle 的对照组必须报告，收益消失则明确归因于上下文恢复成本。

**论文依据与红线自检。** LuaHunt 的单指令语义假设、LOKI 白盒评估；有限模式不是不可枚举，更不是密码学秘密。

### 4.2.3 多格式、变长与操作数交错

**目标与攻击模型。** 主要 cost；对固定 `8:8:8:8` 解码和 M4 小脚本提高适配成本。若规范化后恢复无变化，不计 resilience。

**成本档位与放置位置。** 有界解析 L；区域转码 M。热路径限制最大读字节数及解码阶段数。

**算法步骤。**

1. 每区域选择格式族：短操作数内联、有限长扩展、分离操作数字段流、宏内交错字段。每种格式规定最大长度和唯一终止规则，不允许无界变长整数。
2. 以“区域入口描述→受限前缀→长度/格式→字段→检查位→操作数有效性”的有向依赖解码。长度决定于已知入口状态和有界前缀，不能依赖尚未定位的下一条指令。
3. 为区域建立虚拟寄存器双射 π；对 CellRef、参数序列、VTop 的逻辑索引分别处理，不能把物理置换误用于有序返回序列。区域边界按活值集合转换，循环回边也要复核。
4. 编码字段通过固定宽度可逆映射与滚动状态耦合；显式保留符号、偏置和 RK 种类。拆分片段必须全部到齐并验证后才可触发程序可见效果。
5. 检查位覆盖区域身份、格式、片段长度、字段和值域、入口模式；其功能是检测损坏和不同步。公开白盒 key 的校验不能称抗伪造 MAC。

**不变量。** 对全部合法指令 `Decode(Encode(I,C),C)=I`；合法目标只落在记录端口；任意损坏输入都被有界拒绝，不越界读或无穷扫描。

**失败时降级策略。** 撤销交错/额外格式/置换后重编码；容量或解码证明失败 RV-13/18。

**验证判据。** 长度边界、符号极值、跨片段、截断和非法端口变异；编码/解码两条独立路径比对；格式已知 oracle 攻击测量其净收益。

**论文依据与红线自检。** Rolles 的解释器分析、LuaHunt 的结构无关测试；变长格式不阻止语义探针。

### 4.2.4 寄存器机与栈机

**目标与攻击模型。** 候选 resilience 主要在跨样本工具迁移；双机本身可统一到 SSA，不能保证单样本更难。

**成本档位与放置位置。** 寄存器机用于高频区域；栈机只用于栈高度/成本可控区域，边界转换 M。禁止每个细粒度源操作都跨机。

**算法步骤。** 从唯一语义 IR 分别 lowering：寄存器后端以逻辑寄存器映射值；栈后端对局部 DAG 排序，生成显式 push/pop/dup 与外溢存储。每个 IR 值记录目标栈位置或溢出槽；合流点要求栈高度和槽位类型一致，以并行搬移胶囊解决排列，不能顺序覆盖活值。宏内部可采用不同机种，效果/关闭/call 屏障两侧不得随意交换。跨机 ABI 传递活值、VTop、CellRef、Pending、Ctx；浮点或 Lua 对象值原样传递，不数值重新编码。

**不变量。** 每个活 IR 值有唯一正确表示；栈不欠载、不越界；n 个含 nil 结果仍有 n 个栈槽；转换不制造源堆别名变化。

**失败时降级策略。** 失败区域保留寄存器机；如果边界不能证明则整原型只用一种已验证后端。

**验证判据。** 两后端对同 IR 的三方差分；对攻击器提供统一 SSA lifting 的强对照，测剩余适配成本和工具迁移成功率。双机标签去除后无收益则只计 cost。

**论文依据与红线自检。** Clyde dual VM 是工程方向参考，不是证明跨 Lua 三版本正确或抵抗 LuaHunt 的论文定理。

### 4.2.5 handler 等价变异

**目标与攻击模型。** 修复 M3 的直接字节指纹，并测试规范化、数据依赖切片和 Syntia 风格综合后的残余收益。md5 不同仅是必要的工程检查。

**成本档位与放置位置。** 模板证明离线 H，实例 L/M；热 handler 只选预算内实现。

**算法步骤。**

1. 每个启用的语义槽登记至少 k 个已证明的**不同结构骨架**，k 在预设中冻结；命名、常量和寄存器编号变化不计骨架。候选包括不同中间状态分解、分支求值顺序的等价形式、DAG 调度、寄存器/栈表示及部分共享 handler。
2. 模板契约含输入域、位宽、读写集、效果顺序、退出方式、资源界。只对已证明纯整数私有运算做等价算术；对可能触发元方法或浮点舍入的源运算禁止随意结合/交换。
3. 每 chunk 先选择骨架，再参数化；实例证明之后才进入生成。模板库不足 k 时保留正确配置但取消该槽的异构预设资格，不制造无意义 junk 填数。
4. 对 N 个冻结构建种子提取 handler 机器指令体、程序载荷和 dispatch 子图：记录 md5 以对齐历史测试，同时记录 SHA-256；再去掉命名、地址、常量重命名和布局，计算 CFG/效果 DAG/语义切片签名，聚类检查真正骨架数量。
5. 在保留语义的前提下若样本重复，不悄悄重抽 seed；生成器修订后按完整冻结样本重跑。单次改名不会改变编译后的 body，不能记完成。

**不变量。** 所有模板实现同一宏语义和效果轨迹；实例参数满足域；相似性审计不反过来诱导不安全改写。

**失败时降级策略。** 停用模板/依赖实例，退回已证明骨架；k 或 N 异构性不达标只撤销对应保护等级。

**验证判据。** 原始 handler body/程序体/dispatch 在 N 样本分别全不重复；规范化骨架不少于冻结 k；局部和全程序差分、错误变异检测、跨样本语义分类准确率同时报告。

**论文依据与红线自检。** Rolles 结构指纹、LOKI 多样性、GATE-5；仅 md5 改变不构成 resilience。

### 4.2.6 假 handler 与垃圾 opcode 的上限

**目标与攻击模型。** 默认 cost。对可快照枚举的 LuaGadget，多放恒定陷阱通常容易排除；不称为主保护。

**成本档位与放置位置。** 限额体积和离线生成；正常执行不应额外承担 H。

**算法步骤。** 从已验证真实宏族中选择语义完整、效果受约束的辅助 handler；可以让同一物理槽在真实可达上下文执行真实宏，在另一上下文执行私有管理宏，所有可达组合有规格。不可达假 handler 与陷阱有证明，不能伪装成合法默认处理。估算可达模式数与探针预算，只有预算内未能枚举时报告“本预算下未完成”，并给上下文 oracle、校验已修复的攻击对照。额外未知上下文若不参与真实输出依赖，切片可删，收益记零。

**不变量。** 有效程序从不进入未经证明的假语义；无效字节不无限循环；有限状态始终可被理论枚举。

**失败时降级策略。** 优先删假 handler；模式或不可达性失败 RV-12/19。

**验证判据。** 有效路径假陷阱命中 0；移除假 handler 的消融说明查询开销变化；不得把变异全部被校验拒绝计作 LuaHunt 无法恢复。

**论文依据与红线自检。** LuaHunt 结构无关测试与 Rolles junking 批评；有限空间“不可枚举”要求否定，不给伪证明。

## 4.3 程序体编码与加密

### 4.3.1 密钥流、路径状态与重同步

**目标与攻击模型。** 候选 resilience 仅指局部切片需携带更多路径/状态依赖；独立字节流白化为 cost。白盒对手可以把整个必要解释器子集带入切片，不承诺“任何独立解码器都不可能”。

**成本档位与放置位置。** 滚动更新 L；有限模式多份编码增加体积 M；运行期全区域转码 H 默认关闭。

**算法步骤。**

1. 分开三个对象：存储编码材料 S、有限控制模式 q、运行期表示上下文 W。S 的材料在公开产物内可重构；不声称隐藏 S 是安全根。q 随已经执行的宏/出口更新；W 可附带私有路径摘要和来自合法输入的已有 K，但不改变逻辑程序。
2. 为每个区域 e 求可达入口模式集合 Qₑ 的不动点；对每个 `(e,q)` 生成匹配的有界载荷视图。顺序解码的流状态从该入口确定，按宏和出口标签推进；同一路径的全部有效字节都有一致编码。对 Qₑ 设上限，不能以无限枚举历史制造不可完成的编译。
3. 目标存在不同路径历史时，以显式入口模式选对应视图；不把任意滚动 hash 直接当作唯一静态密文的解密 key。若使用运行期 W 表示，则先按已知存储规则解得局部字段，再在同一胶囊内转换为 W 下的临时表示，后续真实 use 消费该表示；记录这仍留下存储层可恢复面的事实。
4. 每宏在结果提交后计算 `q′=F(q,宏种类,出口)`、`W′=U(W,已验证中间量)`。分支依据原程序真实条件先选出口，再从该出口契约确定目标入口、q′和局部流初始化；合法合流不依赖猜测 key。跨区域入口字段与检查位共同验证。
5. 错误/异常不走“找一个能解码的 seed”路径：原程序错误直接传播；被源 pcall 捕获后在调用者已保存的 continuation 恢复。yield 保存未提交阶段和上下文，resume 继续该阶段；已提交效果不能重复。递归、重入和不同协程各保存自己的状态。
6. 正常重同步只允许在编译器证明过的入口；允许把历史归约为有限 q，但要量化这种归约给攻击者提供的切片边界。若增加路径摘要却没有不可消去 use，删掉并记收益为零。

**不变量。** 全部有效边都有唯一入口视图；编码器、handler 和重同步对同一状态转移一致；每次物化所需材料已定义，无循环密钥依赖；流计数回绕有规范。

**失败时降级策略。** 减少模式/缩小区域；回独立有界编码只标 cost。解码闭包、yield 恢复或合流失败 RV-12/13/08，当前候选不提交。

**验证判据。** 菱形合流、非结构化回边、长循环回绕、嵌套错误捕获、yield 和重入全矩阵；攻击器分别拿到存储层解码 oracle、入口模式 oracle，测完整语义恢复的剩余难度。

**论文依据与红线自检。** Rolles §17.2(c) 指出独立切片的弱点；本设计增加切片闭包，不将相互调用/交织命名冒充不可切片定理。

### 4.3.2 常量跨步骤物化

**目标与攻击模型。** 主要 cost；与真实计算共享经证明的中间量时作为候选 resilience 测试。动态 trace 读出明文属于预期攻击，不声称运行期常量保密。

**成本档位与放置位置。** 整数/布尔固定步骤 L；字符串分片 M，长串初始化 H。热路径禁止反复拼接长串制造高分配。

**算法步骤。**

1. 以类型化二进制规格保存程序常量：整数保持确切位宽；浮点保留目标构建可表示的位模式与子类型；字符串按字节含零字节；布尔显式标签；nil 是序列/寄存器中的值，不因无表项而失踪。不得经十进制文本往返浮点。
2. 数值、布尔和字符串程序常量进入编码池；格式长度、必要偏移/循环界等解释器结构字面量另列 allowlist。不能声称产物中不存在任何明文数字。
3. 为每个站点制定物化 DAG：片段读出→有界变换→与当前表示上下文结合→类型重建→原 use。解码管理步骤可交错于纯私有计算；不得跨原程序效果屏障移动物化错误/分配。常量到达其真实 use 前不集中生成整个明文常量池。
4. 同值多站点可选择不同 DAG 和参数，但源身份/相等行为必须保留；不要把“缓存命中/不命中”改变的 GC 副作用忽略。按热度选择局部缓存时，记录明文生命周期和切片风险；若无法满足预算则撤销逐站点重物化。
5. 池索引、分片长度、宿主 luac 常量数、字符串字节数和区域总量均预先计界。超限先分页并使用已验证的 staging 入口；分页仍超限就 RV-18。staging 自身也必须编译/注入/重验证，不把明文作为错误恢复路径。

**不变量。** 类型、值与原 use 一致；无隐式字符串转数值；所有越界在效果发生前被发现；有效程序不会走 staging 猜测/补零。

**失败时降级策略。** 先撤交织、缓存策略或重物化；仍不能精确恢复类型/位模式则回纯 CFF。减少保护等级可保留正确常量方案，不能容忍数值近似。

**验证判据。** 整数极值、浮点边界、±0、NaN 可观察行为、布尔、空串/零字节/长串、重复常量和池边界差分；独立切片+运行期明文捕获计入对抗评测。

**论文依据与红线自检。** Rolles 常量解码切片；线性 MBA、白化和无 use 的拆分只计 cost。

### 4.3.3 参数、seed 与可恢复面审计

**目标与攻击模型。** 定义可执行的泄漏审计，否定无边界的“静态可恢复面=空”。攻击者知道生成器、参数分布、模板及所有解码规则。

**成本档位与放置位置。** 构建审计 H；运行期参数派生 L/M。

**算法步骤。**

1. 对每种流/白化记录代数条件、周期需求和值域证明；每 chunk 可选择满足条件的参数，参数随机化只算多样性。沿用 LCG 时检验其模数对应的 Hull–Dobell 条件，但不能从满周期推出抗恢复性。
2. 分别追踪 build seed、静态可重构初始化量、输入相关 K、运行期私有演化量。污点到达不等于不可折叠：在真实入口条件下做常量传播、符号归一化、store-forwarding 和取值变化证明，排除 `x−x` 等伪动态依赖。
3. 扫描最终宿主常量、私有池、字段、调试/upvalue 名、载荷头和序列化布局，检测字面量 seed、专用 case/handler 映射表、源程序明文常量、离线 proof map、禁止的固定 LCG 指纹。允许的标准格式常数须逐项声明用途；避开教科书常数本身不增加密码学强度。
4. 审计静态及动态数据流能否直接分离全量 blob 解码器、是否一次获得全部宏边界/常量/目标。先跑 M4 式短脚本，再运行可执行解释器和局部求值的白盒攻击，不能只做字符串扫描。
5. 输出 `(禁止显式泄漏项数,预算内已恢复比例,动态合格站点比例,剩余未知)`。第一项可要求为 0；第二项不能以未经证明的“不可恢复”代替；未恢复项按未知报告。

**不变量。** 不在运行期嵌入构建 manifest 或调试后门；动态 K 资格继承 CFF，不因 VM 内部滚动自动获得；公开可逆编码不宣称密码学机密性。

**失败时降级策略。** 静态材料误当秘密、明文泄漏或动态资格不足记 RV-21，撤相应预设；语义正确的兼容产物可以低等级保留。

**验证判据。** 植入已知 seed/case 表/常量的审计变异全部检出；参数约束验证 100%；独立攻击脚本版本与预算可复现。

**论文依据与红线自检。** LOKI 白盒、Rolles 切片和附录 A GATE-9；禁止“换一组 LCG 常数所以安全”的结论。

### 4.3.4 完整性与篡改响应

**目标与攻击模型。** 确保损坏不静默变为错误程序；主要正确性/cost。对手可重算公开校验，故校验不作为阻止 LuaGadget 的主防线。

**成本档位与放置位置。** 入口有界校验 M；每宏必要范围检查 L。全 blob 校验只在允许的初始化预算内。

**算法步骤。** 在可信长度界内验证头、版本、格式、入口模式和局部校验，再允许程序效果。有效输入下所有校验必然通过；错误 seed、截断或无效模式发出确定的保护层错误对象并终止当前运行，不返回默认结果、不挑候选 seed 重试、不继续执行半条宏。已发生的程序 I/O 不承诺回滚，因此“干净失败”指后续不猜测执行；在任意中途篡改下原子回滚整个程序不可保证。原程序自身错误必须沿原通道传播，不改包装为校验错误。

**不变量。** 有效域中的行为等价；无效域中的解析/失败有界；保护层错误与源错误有清晰来源但不泄露 seed/明文目标。

**失败时降级策略。** 有效程序被误拒是语义失败 RV-13；未建模错误/关闭传播 RV-09/07；拒绝候选。不能简单关闭所有检查掩盖不一致。

**验证判据。** 各字段单比特/长度/片段/模式变异、运行前及中途损坏；有效程序误拒 0。攻击评测另提供可修复校验或直接在解码后变异的 oracle，防止用校验堵输入伪造 resilience。

**论文依据与红线自检。** 白盒边界与 fail-loud 工程原则；不把公开校验称抗篡改密码学保证。

## 4.4 解释器生成与自保护

### 4.4.1 dispatch 拓扑

**目标与攻击模型。** 修复单一直筒比较链指纹，测跨样本适配；单纯拓扑变化为 cost，对结构无关 LuaHunt 不预授 resilience。

**成本档位与放置位置。** 如下表；k 个通过验证的拓扑才可启用该预设，建议候选集合从四类中选。

| 拓扑                    | 算法与正确性条件                                                       | 热路径成本与限制                                             |
| ----------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------ |
| 分段平衡比较图          | 按编码标签的有限集合建决策树，每合法标签唯一叶；随机布局保留分区正确性 | 约对数比较；适合 L，禁止退为全量直筒链                       |
| 有界两级分派            | 先解码区域/模式，再在小组选择宏；控制图带下降排名                      | 入口分组加小组选择；L/M，副作用必须有 use                    |
| 私有函数表              | 编码索引唯一选已生成 helper，返回显式 continuation 和结果协议          | 多宿主调用及捕获；M，额外栈/yield/错误前提严，热场景通常禁用 |
| 记录驱动的混合 threaded | 循环读取下一 continuation 记录，段内直连少量微程序，跨段重分派         | L/M；标准 Lua 无原生间接 goto，不用递归模拟无限链            |

**算法步骤。** 为候选 topology 生成 `有效标签→宏入口` 的离线双射证书；布局随机化与真实语义保持独立；对非法标签生成有界失败出口。源层 if/函数表并不是最终拓扑，luac 和外层 CFF 后必须再分类，防止全部被重写为相同图。纯直筒链仅可留作历史对照/兼容，不属于加固预设。

**不变量。** 一次取宏唯一命中；管理图有限终止；函数表不逃逸、不经过源 `_ENV` 查表；多结果和调用错误不因 helper 边界变化而丢失。

**失败时降级策略。** 禁用不满足栈/预算的 topology；k 不足则撤多拓扑预设，保留正确且预算内的已验证 topology。

**验证判据。** 合法标签全覆盖、无命中/多命中均为 0；最终 topology 不同的证据与 M3 哈希/规范化签名同时检查；LuaHunt 使用相同语义测试集。

**论文依据与红线自检。** Rolles 指纹、LuaHunt 结构无关、IOLLVM 分段；禁止把“threaded”写成标准 Lua 拥有硬件间接跳转。

### 4.4.2 handler 生成器

**目标与攻击模型。** 将 §4.2.5 的语义模板落到可验证产物，抵抗仅按字节/局部结构分类；剩余语义恢复难度由实测决定。

**成本档位与放置位置。** 离线生成与验证 H；运行期开销受每个 handler 的原预算约束。

**算法步骤。** 语义宏→选择经过证明的骨架→选择表示和局部调度→生成带作用域的宿主源级 AST→真实目标 luac→独立解码。局部变量 alpha-renaming 只作名字层，不能算 body 异构；算术、分支、调度各有独立开关。记录宏到真实 bytecode 的映射；比较编译前后效果图、参数方向和隐式取指。对宿主 luac 自动生成的 MMBIN/EXTRAARG/VARARGPREP 等重新形成原子单元，不能沿用源 AST 边界。若编译器把不同模板合并为相同体，则该模板对异构性不计数。

**不变量。** 生成器不引入第二套 opcode 语义；所有调度服从效果屏障；宿主源中的操作与目标版本实际生成形式有对应证书。

**失败时降级策略。** 换回已验证骨架并重新编译/验收；局部编译错误、未知模式或异构资格不足分别记 RV-17/02/20，不手工修字节绕过验证。

**验证判据。** 每模板/每版本微语义差分；N 样本的最终 body 哈希、CFG/DAG 聚类与语义分类成功率；全程序连跑发现未初始化私有变量。

**论文依据与红线自检。** Rolles §17.2(a)(b)、GATE-5 方法论；“所有名称都随机了”不满足 M3 修复。

### 4.4.3 解释器自身进入 CFF

**目标与攻击模型。** 外层 CFF 增加解释器恢复所需的控制/数据分析；对手可以先恢复解释器再攻击 VM，须测完整两阶段成本。

**成本档位与放置位置。** 热 dispatch/热 handler 仅 L；一次初始化可 M/H；错误分支仅在正常运行低频且不改变错误顺序时使用。handler 入口若在热循环则按热预算。

**算法步骤。**

1. 解释器真实 luac 产物向 CFF 提交胶囊契约：片段有界读取→格式/长度验证→字段组装→上下文校验；效果操作的 pending/提交关系；开放结果的生产至消费；运行期表示转换与唯一 use。
2. 原生比较/JMP、MMBIN、附加字自动闭合；额外把“不可在中间出现 CFF 注入的解码/提交区间”登记为单/多端口胶囊。不把整个解释器主循环一概原子化，也不把原子性误当禁止 Lua 自身 GC/yield。
3. CFF 私有槽位从宿主 bytecode 活跃性/top 重新计算；VM 的长期寄存器文件、帧、Ctx 在被证明安全的宿主局部或 upvalue 中保持 GC 根。不能把它们放在物理帧顶之外，更不能假定 callee 只用 20 个临时槽位。
4. 解码阶段一般不得 yield；原语义可能 yield 的阶段必须具备 Pending 证书且 CFF 不能拆坏其恢复关系。新 CFF 控制包与 VM Ctx、源 CFF 控制包三者分配独立命名空间。
5. 验证顺序：未自保护解释器正确→外层 CFF 局部证明→组合模拟→终态常量处理→最终字节码独立复核→真实运行差分和性能/攻击评测。

**不变量。** 外层 CFF 保持整个解释器行为，包括错误、yield 和私有状态；新增管理步骤有限；源 CFF 保留证书与解码胶囊证书均未失效。

**失败时降级策略。** 撤销解释器 CFF 的高成本/冲突特性，再回其已验证配置；若基础 CFF 仍不安全，则只撤解释器自保护，保留已验证 VM；若组合仍失败，原型退纯 CFF。

**验证判据。** 三类状态无写别名；热循环 p95/分配数不越预算；注入前后 Pending 恢复轨迹一致；攻击器能获得内层 VM trace 的强对照必测。

**论文依据与红线自检。** 冻结附录 A 全部 CFF 闸门、Collberg/NOP-RL；不以“嵌套层数”计强度。

### 4.4.4 真实 luac 原型注入

**目标与攻击模型。** 维持直接在官方 Lua 加载的产物与唯一 ABI；注入机制本身不计 resilience。

**成本档位与放置位置。** 离线编译 H；宿主初始化 M/H、调用入口 L/M。

**算法步骤。** 对目标版本用真实 luac 编译解释器模板和 wrapper；独立解码其参数、vararg 标记、子原型和 upvalue 描述符。按符号化角色绑定解释器入口、载荷、池、头、私有上下文工厂及源 `_ENV`，然后重定位为合法描述符。不得按固定 upvalue 下标推定 `_ENV`，不得覆盖用户原 `_ENV`。每个活跃调用/协程获取独立可变帧；只读载荷可共享。字节读取、精确数值物化所需的库原语若作为宿主依赖，必须由既有可信加载契约提供或证明其在该环境下可用且未被替换；不能从用户可变全局中静默取到不同函数。混合闭包引用/共享 cell 依据 §4.1.3 的接口证书装配，最后重解码整个 chunk。

**不变量。** 官方 loader 接受；父/子描述符无悬空；依赖来源明确；wrapper 维持函数身份和返回数量；维护映射不注入到生产载荷。

**失败时降级策略。** 注入/捕获/环境契约失败分别 RV-17/06/24；回该原型 CFF 快照，重新装配引用关系，不留下半注入子树。

**验证判据。** 三版本真实 loader 加载、父子交叉模式、`_ENV` 替换与别名、递归/重入、同一闭包重复返回、nil 多返回值和 C 函数栈压力测试。

**论文依据与红线自检。** 复用题设已验证注入资产，新的桥接条件单独证明；不要求定制 Lua VM、FFI 或默认可用的 debug.upvaluejoin。

## 4.5 VM IR 内的参与式干扰

### 4.5.1 参与计算并抵消的垃圾链

**目标与攻击模型。** 默认 cost；对数据切片和代数归一化测量。只有对已冻结攻击集的实测剩余收益才升级为候选 resilience，不能只证明“有 use”。

**成本档位与放置位置。** 固定宽度私有整数链 L；跨区域链 M，热循环仅短链。

**算法步骤。** 在效果 IR 上选择有类型证明、不会触发元方法的私有值 v；引入可逆表示 `v′=Tₜ(v)`，随后至少一个真实宏/状态更新消费 v′，在规定边界通过逆变换或等价表示恢复原效果。设计关系同时覆盖有符号回绕、移位宽度和值域；禁止在 bitwise 混合 MBA 中塞入运行期伪装的 0/−1。跨调用持久值按普通 VM 状态管理，不占宿主不安全栈槽。编译器保留合同标记防自身 DCE 删除，但该标记只影响离线规划，不能靠强制保留无 use 的指令满足要求。删除定义或替换其 use 应产生反例；代数全局抵消可能仍可消去，记 cost。

**不变量。** 对源状态投影为恒等/正确宏变换；中间数据不逃逸、不新增源元方法/错误；所有定义有实际语义 use。

**失败时降级策略。** 删除整个依赖链并重建宏，不能只删抵消端；RV-14 或 RV-23。

**验证判据。** 位向量证明、小域穷举、真实 VM 边界、def-use 删除变异；goomba/GAMBA/e-graph 化简后的剩余图与攻击耗时单独报告。

**论文依据与红线自检。** Rolles §17.2(b)、GAMBA/MBA-Blast；原指令仍字面保留且仅加 junk 不算 handler 异构。

### 4.5.2 VM 层不透明谓词

**目标与攻击模型。** 程序相关关系为候选 resilience；简单整数同余与非平方模板只计 cost。攻击者可观察 Ctx/虚拟寄存器并建立符号关系。

**成本档位与放置位置。** 私有整数关系 L；私有结构/图 M/H，仅冷位置且分配透明已证。

**算法步骤。** 继承附录 A 模板契约，输入改为 VM 层类型化状态及其范围证书。每实例声明“在哪些入口不变量下恒真/恒假”，不得宣称对任意被篡改状态恒定。选择不同结构模板和参数，从已有 K/Ctx/程序派生关系接入；纯内部可静态推导量仅算状态相关。真假出口默认收敛为同一合法语义；带陷阱的非收敛出口额外证明不可达。对模板规格、实例 IR、私有编码、生成 handler、外层 CFF 和常量终处理后的真实字节码逐级复核真值与分支极性。

**不变量。** 类型/位宽/真值前提在每次到达成立；谓词求值无源可见副作用；两条允许路径均有限。

**失败时降级策略。** 实例失败撤销该实例，模板级反例停用全族并回放历史种子；依赖陷阱的候选一律重建，不重抽参数掩盖。

**验证判据。** GATE-5 的规格证明、小域穷举、全族边界+随机采样、包装器极性、故障注入、加密后复验全部保留；“恒真模板抄成恒假”、k/C 极性翻转和模宽错误必须检出。

**论文依据与红线自检。** Collberg、附录 A GATE-5、LOKI；无 `nil==nil`、单模板族或随机 MBA 未验实例。

### 4.5.3 jump 干扰、landing pad 与 pc 校验

**目标与攻击模型。** 跳板和死块主要 cost；目标解码若与真实上下文有关，测试对路径恢复的增量。动态 trace 与合法边 oracle 为必测对照。

**成本档位与放置位置。** 热边最多固定小深度 L；温/冷边允许有预算的多段 M，禁止真实死循环当保护。

**算法步骤。**

1. 逻辑目标以编码端口描述表示，经多步可逆解码到 `(子程序,区域,入口模式,偏移)`，每一步有范围与下降排名。landing pad 验证入口、活值表示与流模式后才进入宏。
2. 按真实 CFG 的入边和上下文生成跳板；对多端口区域保留各端口。不得让跳板落入宏片段、EXTRAARG 对应的中间数据或尚未提交的效果阶段。
3. “pc 中毒”只定义为**逻辑 pc 的临时编码表示**：中间物理值可以不是合法目标，但直到经证明的逆变换完成都不得取指。所谓自愈仅指正常逆变换；检测到错误不得猜回最近目标或默认块。
4. 默认不生成无限环。若为了对照加入不可达 VM 死循环/假目标，需与 CFF 同等强度的不可达证明、有限解码边界和独立开关，且永远只算 cost。该证明不能依赖“通常不会出现这个输入”。

**不变量。** 正常控制管理图有有限排名；每条有效源边唯一对应一条目标路径；假目标命中 0；源非终止不能由新增管理循环伪造。

**失败时降级策略。** 删多段跳板、pc 表示变换和陷阱依赖闭包，回直接合法端口；不可达证明失败 RV-19，控制闭包失败 RV-12。

**验证判据。** 全有效边/端口证书、最坏跳板深度、跳板删除/目标偏移故障注入；路径 trace 恢复成功率与额外成本共同测量。

**论文依据与红线自检。** Lebedev 的约束、Rolles 和附录 A；源级无限环/非法 pc 不用作反分析惩罚。

### 4.5.4 每站点实例与唯一性

**目标与攻击模型。** 降低跨样本站点指纹迁移率；多样性指标不能替代语义恢复成本。

**成本档位与放置位置。** 离线审计 H；运行期不为填充唯一性添加无用计算。

**算法步骤。** 为每站点分配离线身份，参数导出按版本/原型/宏/阶段域分离。先对规格 AST 做 alpha-renaming、常量占位、交换律规范化、死定义清理，再形成结构签名；另外保存含参数的实例签名。实例要求无意外重复，模板类别分布与规范化骨架数另设门槛。站点数远多于模板数时，不宣称每站点规范化结构都唯一；有限库若无法满足请求的唯一性数量，报告容量不足。签名及去重索引不随产物发布。

**不变量。** 同种子同配置生成同一选择；签名独立于地址、局部名；唯一性不能侵蚀类型/效果证明。

**失败时降级策略。** 去除异构预设资格或调整生成算法后完整复测；不能在结果表中隐藏碰撞站点。

**验证判据。** 实例碰撞率、模板集中度、规范化骨架数、跨 N 样本语义迁移成功率分别给出；所有实例证明覆盖 100%。

**论文依据与红线自检。** LOKI 的站点/模板白盒视角；参数很多不等于模板很多，不称排列数为攻击复杂度。

## 4.6 双层总装配与组合证明

### 4.6.1 总流水线及 CFG 所有权

**目标与攻击模型。** 防止 pass 相互拆毁保护或语义。嵌套收益需最终产物实测，不能把两层单独成绩相加。

**成本档位与放置位置。** 离线多阶段验证 H；运行期成本包括源 CFF 被解释后的放大与外层解释器 CFF。

**算法步骤。**

| 阶段                             | 产物与所有权                                            | 下游权限                                                            |
| -------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------- |
| 原始 luac/上游保护               | 原生 proto、字符串解码胶囊、克隆/陷阱、寄存器/_ENV 合同 | 第一层 CFF 按附录 A 处理，证明陷阱不可达                            |
| 第一层 CFF                       | CFF 原生指令流、端口/控制包/谓词证书                    | 源程序这一原生表示的最后整体 CFG 重建                               |
| VM lift                          | 与原生图精化对应的效果 IR                               | 不去平坦化，不拆源原子单元；可在独立私有 ISA 表示中融合/表示变换    |
| VM encode                        | 私有载荷、入口/池/宏合同                                | 作为数据装配；任何后续变更必须走相同编码器和再验证                  |
| 生成解释器→真实 luac             | 新生成的宿主原型、解码/提交胶囊                         | 建立全新的宿主 CFG，尚未经过其最终 CFF                              |
| 解释器/所有新宿主 wrapper 的 CFF | 外层自保护字节码                                        | 对这些宿主原型的最后整体 CFG 重建；可按预算拒绝                     |
| 注入/重定位、常量终处理          | 终态 chunk                                              | 注入只装配已验证原型/描述符，不暗改内部 CFG；常量阶段仅受限局部展开 |
| 终态验证                         | 唯一可发布产物及离线证明包                              | 从真实字节重新解码，不复用过期 CFG                                  |

VM lift/encode 是冻结契约明确允许的**表示边界**，不是在第一层 CFF 字节码上再跑一个重建 pass；它保留被解释程序的 CFF 语义。第二次 CFF 针对新宿主表示。若把“最后”解释为此后连新解释器的 CFG 都不能生成，则任务流水线逻辑矛盾；本设计严格使用按表示/原型划分的所有权，不修改第一层合同。

第一层若已经做过受限常量加密，其解密胶囊是 lift 输入语义的一部分，照常保留。最终宿主常量处理不得对私有 blob 二次重切字段、偷偷重排 VM 跳板；如需包装 blob 存储，使用声明过的外层数据胶囊并重做组合验证。

**不变量。** 每种表示有唯一 CFG 所有者；真实输出每阶段重新解码；字符串解码、参与式垃圾链、克隆共享捕获、陷阱、MM 尾和 `_ENV` 绑定都有跨阶段合同。

**失败时降级策略。** 撤销破坏合同的最小下游特性重建；无证书 RV-04/22。不能保留半加密或半注入产物。

**验证判据。** 对合同逐一做破坏变异，最终验证器全部检出；报告最终实际保留特性而非请求开关数。

**论文依据与红线自检。** 冻结附录 A §7 与翻译验证；不以“在新层所以可随便消除 CFF”规避契约。

### 4.6.2 外层 CFF、内层 CFF 与可选 VM-in-VM

**目标与攻击模型。** 区分三种嵌套，测整条攻击链：先恢复宿主解释器→恢复私有程序→恢复源 CFF。攻击者可绕过某层做端到端语义综合。

**成本档位与放置位置。** 前两种为本设计常规候选；VM-in-VM 为 H，默认关闭，仅预算允许的冷原型/局部核。

**算法步骤。** 外层 CFF 管理宿主 handler/解码循环；内层 CFF 控制包作为 VM 程序数据保留，二者不共享控制槽。若启用 VM-in-VM，以同一 IR 和已验证能力表把某解释器计算核再 lift，显式截断层数 d、帧大小和各层重入关系。设第 i 层每逻辑步骤平均需要 aᵢ 个下一层步骤，则运行成本近似原步骤数乘 `∏aᵢ`，另加解码/分配/跨层调用；不能按 d 线性预算。先按最坏画像预测，再实际测量；收益必须扣除相同膨胀预算下的其他方案收益。

**不变量。** 每层有独立模拟关系及下降排名；跨层错误/yield/CellRef ABI 仍可组合；不无限自虚拟化。

**失败时降级策略。** 先撤 VM-in-VM，再按外层 CFF 配置降级；层间 ABI 不能证明则 RV-22，不保留随机“多数输入能跑”的嵌套。

**验证判据。** 逐层及端到端差分；有内层 trace oracle/直接语义综合的攻击；额外层的增量置信区间与性能预算同时达标才开放。

**论文依据与红线自检。** Collberg 成本、LOKI 白盒、Rolles VM 恢复；层数不是 resilience 指标。

### 4.6.3 组合模拟与事务提交

**目标与攻击模型。** 以每产物证明约束复杂变换器，正确性优先。此项不计对抗收益。

**成本档位与放置位置。** 离线 H；证书不上线。

**算法步骤。**

1. 对原型保留源快照 P₀、已验证 CFF 快照 Pc、未自保护 VM 宿主 Hv 和最终候选 Hf，附对应摘要，所有构造在事务副本中完成。
2. CFF 模拟 `Rc(P₀,Pc)`；lift/解释关系 `Rv(Pc,Hv)`；宿主 CFF 与常量终处理模拟 `Rh(Hv,Hf)`。组合为 `∃Pc,Hv: Rc ∧ Rv ∧ Rh`，堆/函数身份映射、错误和协程事件的对应关系也必须可复合，不能只串联 pc 映射。
3. 每个管理段给有限停顿排名；区域循环给不变量而非仅展开若干次。对源无限执行验证对应有限前缀和目标无新增纯管理发散；每原型的正确性要在满足 ABI 的任意调用者上下文中成立。
4. 生成器提供证书，独立验证器从最终字节码和私有载荷重建关系。参考语义不得完全复用 emitter 的操作数解码路径，否则 SETI/SETLIST 同源错误会一起通过。
5. 失败先撤导致义务失败的 VM 新特性闭包，重建仍失败则撤解释器 CFF；再失败该原型回 Pc。回退后重新验证父子引用和接口，最后一次性提交每个原型及其相容的注入元数据。

**不变量。** 不输出半提交；unknown 与 timeout 不等于证明；不修改冻结的 Rc 来迁就 Rv；回退资产本身仍须合法。

**失败时降级策略。** RV-15/16/22；若 Pc 无效则按附录 A 退 P₀，不能称“纯 CFF 通过”。无效原输入单独 INPUT_REJECTED。

**验证判据。** 组合证明全覆盖、各退路与引用重装配测试 100%；任一局部效果删改都应使证书失败；最终执行的产物摘要必须匹配已验证摘要。

**论文依据与红线自检。** Necula translation validation、Alive2 有界检查只能找反例、附录 A 有限停顿模拟。

**论文依据与红线自检。** 官方源码是语义权威；LOKI/Necula 的验证方法不替代 Lua 细节。源码已核对不等于目标实现已完成验证。

### 4.7.2 支持矩阵、拒绝底线与覆盖 floor

**目标与攻击模型。** 明确支持子集和固定分母；拒绝难例不得提高成绩。

**成本档位与放置位置。** 离线准入；被拒原型保留第一层成本。

**算法步骤。** 以题设 `18 identical / 36 refused / 0 failed` 的 **54 个固定测试身份**登记基线，先恢复每个身份的版本/原型/配置归属；不能误写为每版本各 18。若实际脚本的统计单位不是测试用例，按原始单位冻结并公布映射。设每版本旧成功集合 Bᵥ 和基线各覆盖维度 Cᵥ；新预设要求 Bᵥ 中每项继续成功、Cᵥ 不下降、全体 failed=0。固定 54 项的同口径汇总至少 18 identical、至多 36 refused；新增测试另列，不稀释旧分母。若发现旧版真实错译，立即修复或拒绝并阻断晋级，不为 floor 保留错误。

三版本各自必须在下列每个最小支持族中有至少一个已证明且通过最终差分的代表，再称“三版本 VM 基本预设”；每族还有固定的边界/极性子矩阵，不能一个例子代替全族测试：

| 支持族              | 最小接受范围                                     | 尚无证书时的边界                              |
| ------------------- | ------------------------------------------------ | --------------------------------------------- |
| 类型化值/搬移/控制  | nil/布尔/整数/浮点/字符串、MOVE、分支和跳过组    | 精确位模式/错误行为不明拒绝                   |
| 纯数值/位操作       | 类型与范围已证明的操作及返回                     | 潜在元方法或源错误无匹配桥接拒绝              |
| 表访问/构造         | 已验证 native table 胶囊；SETI、SETLIST 版本形式 | 元方法、遍历/长度/分配观察不受支持则拒绝      |
| 调用/varargs/多结果 | 无 TBC、ABI 已证的调用；所有 nil 位置保数目      | 未建模 yield/尾调用/5.5 vararg 扩展不混入支持 |
| 数值循环            | 初始化和范围已证明的整数与浮点路径               | 错误转换和溢出计数不明拒绝                    |
| 闭包/upvalue        | 无捕获或身份/共享已证的捕获                      | 混合可变捕获和重入边界不明拒绝                |
| 冻结 CFF 控制结构   | 完整控制包、谓词、分段管理与其 use               | 合同不闭合拒绝整个原型 VM                     |

泛型 for、TBC/CLOSE、任意元方法、任意协程、5.5 GETVARG/ERRNNIL、非常规多端口分别作为扩展能力，不因 opcode 已解析就显示支持；每版本每形式有明确 ACCEPT/REFUSE/待实现状态。首次发布若任一最小族尚未完成，只能声明对应更小子集，不能授予上述基本预设名称。

**不变量。** 每原型返回 `APPLIED_VM(actual,proof)`、`UNCHANGED_VM(RV,仍可用的CFF快照)` 或 `INPUT_REJECTED`。单原型拒绝不意味着整个 chunk 无产物；脚本中预期只测该原型 VM 的模式用约定 exit 3 报拒绝，验证失败用不同的非成功码，不能混成 refused。聚合 chunk 另用 manifest 报部分覆盖。

**失败时降级策略。** 根因驱动降级；floor 不达标阻断新预设。用户没有授权降低 Obs，因此未知语义只能拒绝。

**验证判据。** 旧成功身份集合包含关系、各版本/各族 floor、热度加权覆盖和所有拒绝根因；模板/构建 seed 均不得改变测试分母。

**论文依据与红线自检。** 附录 A GATE-6；不凭新增容易样例或拒绝困难样例提高覆盖率。

### 4.7.3 三版本真实执行差分

**目标与攻击模型。** 发现错译、未初始化读和进程污染；不把测试通过或攻击器挂死作为保护成功。

**成本档位与放置位置。** 仅验证环境 H，每次执行独立资源配额。

**算法步骤。** 对同一版本构建、输入和外部事件分别运行原程序、纯 CFF、VM 兼容配置、各新特性及终态组合。记录完整事件轨迹和明确 n 的结果序列；输出文本只是其中一项。多进程重跑检测随机布局敏感性，同一进程多次调用检测残留状态，交错协程检测私有状态污染。只按预先冻结的 Obs 规则规范化地址/身份映射；不可删除错误、nil、次序或把整数/浮点都转字符串。

每次执行创建独立进程组和唯一临时目录，启动前登记 pid、开始时间和预算；单调时钟看门狗到限终止整个进程组并回收等待状态，确认无遗留子进程再继续。macOS 不依赖系统自带 `timeout`。输出、stderr、退出/信号、超时、资源用量和产物摘要统一归档；验证脚本的超时为 UNKNOWN，不计 identical/refused。

**不变量。** 不同版本分别对自己的原版比较，不要求跨版本程序行为相同；所有要求测试都有最终状态；未运行或被终止不能填通过。

**失败时降级策略。** 观察反例 RV-16；验证未知 RV-15；进程清理失败暂停测量并清理环境，不将污染结果算性能/对抗成绩。

**验证判据。** `tools/verify-all.sh`、`verify-cff.sh`、`verify-vm.sh` 接入同一记录格式和看门狗纪律；要求测试完成率 100%，残留进程 0，观察不一致 0。本文件规定如何复用题设基建，不声称本次已运行这些脚本。

**论文依据与红线自检。** 附录 A 差分矩阵、LOKI fuzzing；超时不证明等价或不可破解。

## 4.8 验证、攻击与发布制度

### 4.8.1 多维验证与闸门算法

**目标与攻击模型。** 先证明/差分语义，再评价白盒恢复成本；不以哈希、膨胀或工具崩溃代替收益。

**成本档位与放置位置。** 离线 H；测试集合和预算先冻结。

**算法步骤。**

1. 矩阵轴为精确三版本×原程序/纯 CFF/VM 兼容配置/每特性/关键两两组合/依赖闭包/每预设/压力配置/每条退路×程序语义族×构建种子×输入×重复执行。两两组合用于补充，不替代实际发布组合全测。
2. 每个样本先查合法性和逐产物证书，再微语义对照和端到端差分；再做性能、异构性、静态泄漏和攻击。任一正确性反例停止候选晋级，并将最小反例永久入库。
3. 对有限位宽模板做规格证明、小域穷举、边界、随机采样和定向错误注入；堆/调用/yield 用关系不变量与效果契约。仅有界展开通过不得写为无界循环正确。
4. 将所有闸门与实际特性绑定，而非与营销预设名绑定。依赖项未通过，关闭其上游请求；不能偷偷启用依赖。
5. 对正确但收益不足的产物降低声明等级；已知错译不得保留。最终闸门和回退数字见 §6。

**不变量。** 必需证明覆盖 100%；要求矩阵无 unknown/未执行项；基线资格、强化资格和覆盖统计分别管理。

**失败时降级策略。** 按 §5 根因与 §6 闸门撤销最小依赖闭包；新版本/新模板/新 emitter 使相关绿色状态失效，必须重验。

**验证判据。** 所有零容忍项为 0，所有要求测试完成；最终 checksum/摘要与签收产物一致；发布记录能够再生成。

**论文依据与红线自检。** Necula、Alive2、LOKI、附录 A GATE-0..10；验证预算耗尽只能拒绝/未知。

### 4.8.2 白盒对抗矩阵与 LuaHunt 成本曲线

**目标与攻击模型。** 测量语义恢复而非反编译界面效果。攻击者拥有生成器、算法、模板、规则、可执行产物与任意合法输入，允许构造适配器、读取/修改解释器状态及跨样本训练。

**成本档位与放置位置。** 攻击环境 H；记录固定机器、并行度、工具版本和人员投入口径。

**算法步骤。**

| 攻击组                 | 实施与增强对照                                                               | 成功条件/主要指标                                 |
| ---------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------- |
| unluac 与宿主结构恢复  | 支持精确版本；不支持时经验证 IR 适配                                         | 获得可执行等价表示，非“是否输出源码”              |
| M3 指纹/跨样本分类     | 原始哈希、归一化 CFG/DAG、语义嵌入/分类；训练与隐藏 seed 分开                | handler 语义标注准确率、迁移覆盖、适配工时        |
| M4 静态解码            | 重现短脚本基线；增强到常量传播、模拟 decoder、取解释器切片、字段推断         | 边界/宏/操作数/常量恢复率及完整程序重建通过率     |
| LuaGadget/LuaHunt 风格 | 从真实可达状态取快照，变异单/多 opcode、操作数和上下文；校验修复或解码后变异 | 有效查询数、精确宏转移恢复率、联合 h 与耗时曲线   |
| 动态 trace/切片        | 单路径及多输入；捕捉明文常量、Ctx、虚拟 PC；扩大切片至必要解释器子图         | 覆盖内/外语义恢复率、泛化到未见输入的成功率       |
| Syntia 风格程序综合    | 位向量纯计算和有界宏先适配；对效果宏使用分离的效果规格                       | 综合时间、样本数、隐藏输入差分与规格验证          |
| 数据流/反平坦化        | D810/Lebedev 条件复现；CaDeCFF 思路；内存 SSA、别名、store-forwarding        | 原 CFG/宏 CFG 的边 precision/recall及语义后继恢复 |
| 代数统一化             | GAMBA/MBA-Blast/goomba、e-graph，对跨模板私有计算归一化                      | 可消去管理计算比例及恢复成本变化                  |

LuaHunt 仿真至少分三档：普通入口测试；合法前缀产生的快照；**提供正确上下文/格式/校验修复 oracle**。只在第一档有效的收益必须标明“入口获取成本”，不能称联合语义难度。gadget 被拒绝、攻击工具崩溃或不支持版本须另计，不能当语义恢复失败。

对超指令实验固定语义任务和程序规模，分别改变 h、宏长度、依赖宽度、模式数和机种；报告各点的有效查询数、成功率、完成时间分布及置信区间，比较乘积枚举模型和可分离模型。在未知 h 时用研究者 oracle 标注“实际联合未知量”的参考值，防止把所有字节数当作 h。攻击者恢复一个等价超级宏即算成功，不强求还原源指令序列。

“同一工具不能通吃”以冻结训练集学到的恢复器在隐藏样本上的成功比例、增加适配代码/人员时间来测；构建 seed 变化但无需工具修改就成功，不算达到目标。人日指标必须记录实际人工工作时长，不能把求解器运行一天换算成人日。

**不变量。** 适配器在未保护基线上达到预设覆盖/正确性，才用于评价保护；测试 oracle 强弱公开；时间预算一致，程序体积预算也一致。

**失败时降级策略。** 攻击器适配未完成则该项 UNKNOWN，不发布对应 resilience 声明；收益低于 δ 则撤等级，保留正确的 cost 方案需仍满足性能预算。

**验证判据。** 以“重建程序通过隐藏输入差分/规格验证”为终点；恢复率、查询数、机器时间、人工时间同时报。超时按右删失数据报告，工具崩溃单列；不能将所有超时替换为同一个大耗时后算平均收益。

**论文依据与红线自检。** LuaHunt、Rolles、Syntia、CaDeCFF、Yadegari 等通用语义去混淆方向；不直接迁移不适配 Lua 的工具结论。

### 4.8.3 消融与交互实验

**目标与攻击模型。** 分离真正改变恢复工作的机制与只增加体积的机制。

**成本档位与放置位置。** 离线 H。

**算法步骤。** 固定程序/输入/seed/机器/攻击预算，分别撤销超指令、上下文语义、路径模式、双机、handler 骨架、拓扑、常量交织、VM junk、跳板、外层 CFF；依赖项采用最小完整闭包，不能构造无效半配置。除“完整−单项”外，对超指令×上下文、上下文×路径、双机×模板、内外 CFF 做关键交互组。再做同体积/同延迟的替代配置对照，剔除单靠膨胀获得的超时。使用配对统计和隐藏样本，记录退路实际配置；若某特性使更多原型拒绝，要按固定分母报告。

**不变量。** 对照均语义正确；被撤特性的依赖变化明确；训练攻击器不得看到隐藏测试结果后再选择有利样本。

**失败时降级策略。** 无增益或负收益移出强化预设；不可归因的混杂结果记未知并重设实验，不挑有利 seed。

**验证判据。** 每个 resilience 声明有配对增量及置信区间；cost 特性有放置预算和开启理由；对多项检验使用预先登记的统计控制，不能只报告显著项。

**论文依据与红线自检。** LOKI 白盒评测、Banescu 符号执行评估、附录 A 消融方法；“更乱”不构成实验结果。

### 4.8.4 验证基建与回归维护

**目标与攻击模型。** 结果可复现，失败能缩减定位；不计 resilience。

**成本档位与放置位置。** 离线 H，按 shard 并发；每 shard 独占临时目录和进程组。

**算法步骤。** 复用题设真实 lua/luac、unluac 与三个 verify 脚本，增加统一 manifest：版本/源码/工具摘要、输入身份、全部种子、请求/实际特性、能力判定、proof 状态、产物摘要、轨迹、资源、攻击器与截止时间。使用 `mktemp` 的独立目录纪律，原子落盘日志；看门狗按 §4.7.3 回收所有子进程。随机测试包括源级生成、合法原子字节码生成、保结构变异、私有载荷变异、模板参数变异和失败注入。反例缩减必须保留版本字段、原子组、观察事件和触发的配置依赖；永久回归存最小例与原 seed，不只存错误输出。

**不变量。** 不共享临时文件/可变缓存污染；同输入配置可重现；故障出现后可追溯全部受影响产物。

**失败时降级策略。** 测量污染、不可复现或证书/产物摘要失配 RV-25；阻断发布。已发布错译停用相关特性组合，按记录重建受影响原型，不仅修改默认开关。

**验证判据。** 故障注入覆盖超时、崩溃、日志中断、子进程遗留和并发；根因记录率/退路测试率 100%；未回收进程数 0。

**论文依据与红线自检。** LOKI fuzzing、附录 A 复现闸门；基建污染不记为“防护使工具失败”。

## 5. RV 根因码与统一降级

每次拒绝记录一个首要根因、所有次要义务、版本/原型身份、失败阶段与最小依赖闭包。码值稳定，之后可加子码但不复用旧意义。与附录 A 的 R 码并存：第一层失败沿用 R，VM 层使用 RV。

| 根因码 | 类别与触发条件                                  | 必须采取的动作                             |
| ------ | ----------------------------------------------- | ------------------------------------------ |
| RV-01  | 输入/构建不可信：损坏 chunk、源码/配置/版本未知 | 无效输入拒绝；合法但版本未知则不 VM 化     |
| RV-02  | opcode/字段/类型语义未建模，包括 5.5 新形式     | 原型退 CFF，禁止默认语义                   |
| RV-03  | 原子组/多端口/CFG 不闭合                        | 撤融合/扩大区域；仍失败退原型              |
| RV-04  | CFF/前置胶囊合同缺失或被 lift 消解              | 撤破坏合同的变换，重新 lift                |
| RV-05  | 参数/多返回值/vararg/VTop 不可证明              | 撤接口方案；原型退 CFF                     |
| RV-06  | upvalue/闭包身份/混合共享 cell 不可证明         | 收缩混合边界；受影响原型退 CFF             |
| RV-07  | 关闭/TBC/尾调用关闭生命周期不明                 | 拒绝相关原型 VM，不模拟猜测                |
| RV-08  | yield/resume/重入/原生不可 yield 边界失配       | 撤对应支持配置；原型退 CFF                 |
| RV-09  | 错误对象/元方法/精确原语义不能对应              | 使用已验证桥接，否则拒绝                   |
| RV-10  | 新分配、GC、弱表、资源失败或源表布局观察冲突    | 撤相关分配/表示；VM 必需部分仍冲突则退原型 |
| RV-11  | 自省、字节码/hook/调试栈/时间观察冲突           | 无既有兼容契约就拒绝变换，不改 Obs         |
| RV-12  | 模式/入口/控制包/路径密钥状态不闭合             | 撤多态/路径特性，从快照重建                |
| RV-13  | 编解码/校验/常量物化错误或有效输入误拒          | 不提交，定位模板/版本记录                  |
| RV-14  | handler/谓词/参与式计算规格或实例不成立         | 停用实例/模板族及依赖候选                  |
| RV-15  | 证明 unknown、超时或必需测试未完成              | 该候选不提交；记 UNKNOWN 非通过            |
| RV-16  | 真实语义差分反例                                | 阻断发布并回放同根因全部种子               |
| RV-17  | luac/注入/描述符/_ENV 绑定失败                  | 回原型快照，重新装配引用                   |
| RV-18  | 原生/私有编码、常量池、寄存器、帧或长度容量超限 | 降低融合/模式/分页；仍失败拒绝             |
| RV-19  | 假目标、陷阱、管理发散可达或未知                | 撤整个陷阱依赖闭包，不留危险边             |
| RV-20  | 异构性/静态恢复/LuaHunt 收益未达标              | 撤保护等级，正确兼容产物可保留             |
| RV-21  | 禁止泄漏或动态种子资格不足                      | 修复编码/审计，撤相关等级                  |
| RV-22  | 层间模拟/跨表示合同无法组合                     | 撤 VM 新特性→解释器 CFF→退纯 CFF           |
| RV-23  | 热度/时间/体积/内存/分配预算超限                | 撤高成本特性；不得削弱语义检查             |
| RV-24  | 宿主库/可信加载/跨边界能力契约缺失              | 不暗依赖用户全局；退原型                   |
| RV-25  | 复现/临时目录/进程回收/摘要一致性失败           | 停止测量与发布，修复基建后重跑             |

统一流程为：**快照→闭世界能力判定→候选规划→证明→真实验证→预算/攻击审计→提交**。失败回到快照，按首要根因撤销最小依赖闭包；不得在已失败的字节数组上继续打补丁。正确性允许子集不等于允许忽略 floor：安全拒绝仍要在固定覆盖分母中计入失败晋级原因。

## 6. GATE-V0..V14：哪个数字恶化必须回退

每个预设预先冻结 `N`（跨样本数）、`k`（每槽结构骨架/拓扑门槛）、覆盖 floor、成本 B、攻击预算、最小收益 δ 和统计方法。可将 **N=32、k=3** 作为首轮工程审计配置；它们是待评估的验收设置，不是研究结论。δ 必须给出具体单位/方向，例如有效查询与恢复时间的配对倍率、迁移成功率差值；没有预登记数值时只能报告实验，不能晋级。

| 闸门                    | 验收条件                                                                                            | 数字恶化/失败后的动作                                                          |
| ----------------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| GATE-V0 结构/版本       | 源/宿主非法组、错字段、错方向、错端口、非法 loader 产物均为 0；实际发射语义覆盖 100%                | 任一非零或覆盖下降：拒绝候选，停用涉及版本/模板                                |
| GATE-V1 翻译证明        | 所需局部及组合证明覆盖 100%，unknown/超时 0                                                         | 任何缺项：该原型不提交，不能以 fuzz 替代                                       |
| GATE-V2 真实差分        | 三版本要求矩阵完成 100%；观察差异、额外错误、错返回数量均为 0                                       | 出现 1 个反例阻断发布；未完成不算 identical                                    |
| GATE-V3 ABI/栈/生命周期 | top、GC 根、捕获、关闭、yield、尾调用关系覆盖 100%，越界/失配 0                                     | 任一失配回退接口/模板/特性组合                                                 |
| GATE-V4 控制/解码       | 有效状态闭包、唯一解码、入口/长度界、有限管理终止全部成立；有效输入误拒 0                           | 任一失败回退多态/路径/编码；不得发明 fallback                                  |
| GATE-V5 模板/谓词       | 全族规格与实例覆盖 100%；真值/极性差异 0；规定错误变异检出 100%                                     | 比例下降或差异出现：停用模板族并历史回放                                       |
| GATE-V6 覆盖/退路       | Bᵥ 全保留，各覆盖 floor 不下降；54 项同口径≥18 identical、≤36 refused、0 failed；根因/退路覆盖 100% | 下降阻断新预设；已发现旧错译优先安全拒绝并修复，不能维持错误 floor             |
| GATE-V7 性能            | 各版本/预设 p95 延迟、最热循环附加成本、体积、峰值内存、分配数均≤B                                  | 任一分层预算超出：降配置；不能用攻击超时抵消性能失败                           |
| GATE-V8 异构性 M3       | N 样本每目标 body/程序体/dispatch md5 与 SHA-256 分别无重复；规范化骨架≥k；最终 topology 门槛达到   | 原始重复或规范化塌缩：取消异构资格；改名/整文件散列不能代替 body               |
| GATE-V9 静态恢复 M4     | 固定短脚本与增强静态攻击成功率/恢复时间达到预冻结改善 δ_static                                      | 改善不足、明文全量解码仍轻易成功：撤静态保护等级，不称 M4 已修复               |
| GATE-V10 LuaHunt        | 有效 gadget 恢复成本/成功率达到 δ_gadget，隐藏样本区间支持收益；oracle 档位全部完成                 | 收益不足或只是校验拒绝：撤 resilience 声明；h 指数模型拟合失败不得宣称指数增长 |
| GATE-V11 迁移/综合/切片 | 动态切片、Syntia 类综合、跨样本迁移和语义恢复达到冻结目标 δ_transfer                                | 一套工具继续同成本通吃：撤相应“人日/难迁移”声明                                |
| GATE-V12 泄漏           | 禁止模式 0；动态合格站点比例达到承诺；无源明文池/seed/case/proof-map 旁路                           | 任一泄漏或比例下降：撤对应特性/等级；不宣称全静态不可恢复                      |
| GATE-V13 组合/复现      | 全部发布组合与降级路径完成 100%，同种子可复现，最终证书摘要一致，遗留进程 0                         | 缺测/失配/进程污染任一出现：阻断发布并重跑                                     |
| GATE-V14 消融与净收益   | 每项 resilience 有固定预算配对增益及区间支持；等体积/成本对照不推翻归因                             | 无贡献/负贡献撤出强化预设；只剩 cost 就按 cost 发布                            |

GATE-V0..V5 的正确性要求、V6 的支持承诺、V7 的预算和 V13 的复现必须同时满足；V8..V12/V14 决定可宣称的保护等级。若样本因超时都未恢复，报告删失下界和未知区间，不能伪造一个足够大的收益倍率强行通过。

## 7. 红线自检清单

| 任务书红线                                         | 本设计的强制自检                                                              |
| -------------------------------------------------- | ----------------------------------------------------------------------------- |
| 单 opcode=单可观察计算为默认                       | 强化配置审计复合宏与联合依赖覆盖；残余基础槽如实统计，兼容配置不冒充强化      |
| opcode 重排当强度                                  | 只计 cost，必须有语义攻击消融                                                 |
| 同模板换常量、结构同构                             | 检原始 body 和归一化 CFG/效果 DAG，k 不由改名凑数                             |
| junking-only                                       | 有真实 use 且删除能出反例；仍能代数消除的只算 cost                            |
| 独立可切片 decoder                                 | 检查可执行切片闭包及 whole-interpreter 攻击；不保证绝对不可切片，失败就撤等级 |
| 教科书参数/字面 seed/明文映射                      | 最终全表示审计；标准结构常数显式 allowlist；随机参数不是密码学证明            |
| 可折叠谓词、单模板、线性 MBA、高熵 state、死环强度 | 原附录 A 红线完整继承；GATE-V5/12 与化简攻击共同检查                          |
| 热循环重手法                                       | 以真实频率分档，handler 入口不自动算温路径；双层乘法成本入账                  |
| 算法保密或不可逆叙事                               | 全白盒、提供 oracle 对照；只依据实测预算宣称恢复成本                          |
| 未验证随机化                                       | 模板规格/实例/编码/宿主包装器/终态验证缺一不晋级                              |
| 错译、未知默认行为、半提交                         | 稳定 RV 码、快照重建、逐原型判定与相容引用事务提交                            |
| 哈希不同就宣称难恢复                               | 原始哈希是 M3 最低检查；语义迁移/综合成功仍算攻击成功                         |
| 超指令必然指数、私有状态必然不可枚举               | 明确否定普遍结论；用有效 h 与固定预算曲线实测                                 |
| 出现错误后悄悄扩大观察容差                         | Obs 冻结；错误文本/表顺序/浮点/结果个数不事后规范化掉                         |

## 8. 按依赖排序的阶段路线图

各阶段都使用唯一实现；新开关默认关闭，只有精确版本上的相应矩阵全绿才开放。下面是实施依赖，不是已经完成的工程状态。

| 阶段              | 算法工作与独立开关                                                                                                                              | 进入下一阶段的条件                                                  |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| P0 冻结与尸检     | 锁定三版本、54 项身份/分母、Obs、预算；复现 SETI/SETLIST/少参数/GATE-5/死循环污染；删除损坏实现生产入口，历史样本仅离线保留                     | GATE-V0/V6/V13 的基线记录可信，无未知统计口径                       |
| P1 唯一语义核     | V_vm、原子 lift、显式 Seq/VTop、最小调用/闭包支持、接口证书、真实 luac 注入；baseline 仍是唯一实现子集                                          | 支持子集 GATE-V0..V6 通过；每条 RV 退路可复现                       |
| P2 可组合执行     | `vm.calls.extended`、`vm.upvalue.bridge`、`vm.yield`、`vm.close`、5.5 新语义分别开关；不相互假定可用                                            | 每能力独立通过完整观察与 ABI 矩阵，再提高覆盖 floor                 |
| P3 联合语义 ISA   | `isa.super`、`isa.context`、`isa.dual`、`handler.metamorphic` 分开；先超指令后上下文，双机独立                                                  | 正确性+预算通过；LuaGadget/oracle 基线与 h 曲线可测                 |
| P4 表示与路径     | `encoding.multiformat`、`encoding.interleave`、`regs.region_map`、`key.path`、`constant.interleave`、`constant.rematerialize`、`integrity` 分开 | 编解码/合流/恢复证书、M4 审计及 cost 净收益                         |
| P5 宿主与 VM 干扰 | `dispatch.*`、`interpreter.cff`、`vm.junk`、各 `vm.predicate.family`、`vm.jump`、`vm.decoy`、`vm.pc_representation` 分开                        | 三类状态隔离、全 GATE-5、外层 CFF 合同和热成本通过                  |
| P6 强化预设       | 固定支持子集与依赖闭包，N 样本异构、静态/动态/综合/迁移攻击、消融与隐藏样本                                                                     | GATE-V0..V14 全部达到预登记门槛，才宣称实测级别                     |
| P7 可选 VM-in-VM  | `vm.nesting` 默认关闭；只对独立冷核且每层有证书的配置开放                                                                                       | 乘法成本仍在 B 内，且等成本对照显示增量收益；否则永久保留为实验方向 |

最先解决的是源语义和组合 ABI，其次才是多态/融合。每次覆盖提升和每次保护等级提升分别签收；任何阶段没有足够证据，都可以输出合法纯 CFF 或已验证 VM 子集，同时准确记录未应用特性。
